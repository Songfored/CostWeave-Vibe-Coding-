# v0.6.3 migration notes

- Active line: `v0.6.3` / runtime schema `v6.3.0` / 33 migrations.
- Migration 033 (`033_joint_plan_route_schedule_search.sql`) adds immutable,
  project-scoped joint-search candidates, decisions and idempotency records.
- Existing EventLog, projections and v0.6.0–v0.6.2 tables remain readable.
- The new service is advisory-only and defaults to zero Provider/network calls.

## API

- `GET /api/v1/joint-search/status`
- `POST /api/v1/joint-search/decide`
- `GET /api/v1/joint-search/{decision_id}`

The POST contract requires `Idempotency-Key` and
`confirm=RUN_JOINT_SEARCH`. The request contains a complete v0.6.3
`JointSearchProblemV1` and a searcher (`greedy`, `beam`,
`successive_halving` or `pareto`).

## Rollback

Do not delete migration rows or modify the new tables. To return to the stable
runtime, keep v0.6.3 records immutable and deploy the prior application with a
backup snapshot; the old execution route remains authoritative because v0.6.3
never activates production routing.
