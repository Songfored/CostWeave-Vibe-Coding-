# 自动实验与账单校准

## 使用方式

双击原有 `start-experiment-lab.cmd`，首页已升级为自动实验台。填写 **API 地址、API Key、模型 ID、接口类型** 后点击“保存接口并自动评测”。来源名称可选，不需要价格，不需要安装依赖、创建数据库或手工运行脚本。

每个连接自动运行一次有限实验。相同连接重复保存不会重新扣费；如果需要更多样本，点击“再运行一轮（8 次）”。多个连接会串行排队，方便区分账单窗口。可随时请求停止后续任务，在途请求不会自动重发。

真实调用的授权来自保存并评测或再次运行的明确操作。仅启动服务不调用模型，不导入旧 `.env.local`，不挪用旧实验预算。当前工作流使用调用次数和 Token 上限控制规模，**未知单价时无法保证人民币/美元/点数金额封顶**。

## 本轮实验设计

任务集固定为 `costweave-auto-text-20260918-v1`，使用固定种子生成八个合成任务。所有接口面对相同任务：

| 任务族 | 两种场景 | 验收方式 |
|---|---|---|
| 计算与格式 | 两组算术和字符索引 | 整数、字符串精确匹配 |
| 清洗与聚合 | 重复记录最后一条生效；全部取消 | ID、数量、分金额精确匹配 |
| 约束与边界 | 合格候选中选最便宜并按 ID 破同分；无合格候选 | 选择与成本精确匹配 |
| 依据提取 | 36 条记录中的指定事实；记录缺失 | 答案与来源精确匹配，缺失时 null |

参考答案由本地确定性逻辑生成，不让另一个模型给分。输入中不传入参考答案。严格检查 JSON 重复字段、字段集合和递归类型；布尔值不能充当整数。输出仅作为数据保存，不执行返回代码。

每轮最多 8 次模型调用，每次 1 次尝试，输出上限 1024 Token，输入请求 UTF-8 字节上限 16384，单次超时 60 秒，整轮 600 秒启动截止。最多排队 16 轮。供应商若不遵守 Token 限制会停止后续任务，已经产生的费用仍需账单确认。身份、网络、协议或用量响应失败会停止该接口当前轮；不会自动更换模型、猜协议重试或循环续跑。答案不正确仍会计入验收失败，并继续剩余任务以便观察质量。

这些是小样本接口实验，不是公开排行榜，也不代表真实多模型 DAG 编排已经完成。

## 真实账单反馈

每轮完成后，在对应卡片填写：

1. 本轮该接口的总账单金额。
2. 单位：人民币 `CNY`、美元 `USD` 或校内点数 `POINTS`。
3. 来源凭据：服务商账单编号或对应时间段。
4. 确认金额只包含本轮该接口用量，不含其他应用、充值或退款。

也可以将对应轮次和提供商账单交给助手录入。总余额变化若混入其他用量，不能准确归属本轮，不会作为可信校准数据。

金额按小数保存。账单登记后，本轮显示“你反馈的提供商账单”作为实际成本；这不表示系统已登录供应商独立核验。未提供账单时实际成本为 `null`，不是零。

未来相同接口配置采用最近最多 10 个完整实验轮次的综合有效单价：

`综合单价 = 同一单位的账单金额总和 / 对应总 Token × 1,000,000`

仅完整成功取得用量的真实轮次参与校准。失败、缺失用量、被取消及离线替身数据不训练费率。接口地址、模型、协议或密钥变化会进入新的校准范围；改来源显示名称不会丢失已有校准。输入、输出、缓存和思考混合比例变化可能造成估算误差；总账单不足以分别识别这些单价。

人民币、美元和点数不自动换算，也不跨单位相加。原始账单、历史费率快照、当时预测和预测残差保留；修正必须引用当前账单版本，新版本追加保存，不静默覆盖。收到真实账单不会改写历史调用用量、降低原有付费实验的金额预算，或修改生产路由。

## 支持的接口

- 通用 OpenAI-compatible Chat Completions：不盲目附加思考参数。
- DeepSeek 官方 Chat Completions：复用非思考 JSON 配置，预填 `deepseek-flash`。
- 新版 GPT Chat Completions：使用 `max_completion_tokens`。
- OpenAI-compatible Responses：非流式文本请求，`max_output_tokens`、`store=false`，从类型化 output 项提取最终文本，不保存思考内容，不执行工具项。

服务商若只支持自定义流式协议、原生 Anthropic、特殊鉴权或不同参数，需要提供其接口规范后适配；不能由模型名称推断。Embedding、GPU 部署、图片/音视频实验尚不属于这个文本实验自动流程。

Responses 契约依据：[OpenAI 官方迁移文档](https://developers.openai.com/api/docs/guides/migrate-to-responses)。

## 存储与工程边界

使用现有 `work/manual-lab` 数据目录：

- `connections.json`：当前 Windows 用户 DPAPI 加密凭据与配置。
- `automation/rounds/<轮次>/report.json`：任务、调用、结果、原始成本预测及状态。
- `automation/rounds/<轮次>/runtime.sqlite3`：现有 ExternalCallAuthority / ExperimentalCallStore 管理的调用账本。
- `automation/rounds/<轮次>/connection.private.json`：该轮加密连接快照，不通过网页返回。
- `automation/invoices.json`：账单修正历史。
- `automation/rounds/<轮次>/reconciled-report.json`：含本轮对账结果的报告。

原有金额预算为默认模式。新增 `usage_only` 必须在实验预算和适配器两侧显式一致，使用单独策略版本 `external-call-usage-only-v1`；不得自动降级旧金额预算。为兼容现有 SQLite 非空数字字段，其内部价格占位为 0；此策略下这些数字不是金额证据，公开调用、汇总、余额和序列化回执均显示未知金额 `null`。用量上限由固定任务计划、调用登记和请求参数共同约束。

启动后不会自动重发中断的轮次，避免无法确认供应商是否计费时重复请求。进程可持续运行，关闭浏览器不影响队列；页面底部停止服务只在队列空闲时可用。关闭服务前可取消排队与后续任务。

验收包括真实 HTTP 链路的离线替身测试、未知价格与旧预算隔离、八项任务执行、重复提交、失败停止、取消、中断、Responses 参数、账单归属、重复账单、追加修正、多单位隔离和后续成本估算。正式供应商连通性仍需用户填入真实 API 后验证。
