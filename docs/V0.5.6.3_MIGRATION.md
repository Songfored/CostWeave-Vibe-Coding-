# CostWeave v0.5.6.3 升级说明

v0.5.6.3 可直接覆盖 v0.5.6.2 程序并继续使用原数据库。首次启动会自动应用 migration 016，将 Runtime Schema 从 `v5.6.2` 升级为 `v5.6.3`；Run Projection Schema 继续兼容 `v5.5`，旧运行投影无需重写。

## 默认行为

升级后不会自动连接任何模型，也不会产生付费请求。下列开关默认均为关闭：

```powershell
$env:COSTWEAVE_EXPERIMENTAL_ADAPTERS="0"
$env:COSTWEAVE_PAID_CALLS="0"
```

仅打开第一个开关可用于经过显式配置的本地 Loopback 实验；远程或任何计费连接必须同时打开第二个开关。开关本身不等于授权：调用前仍必须注册实验总预算和 Provider 子预算。

## 新表

- `external_experiments`：不可变实验预算配置与冻结状态。
- `external_calls`：逻辑调用、请求指纹、预留/实际费用与终态回执。
- `external_call_attempts`：逐次尝试 Token、费用、时延、限流与错误分类。
- `shadow_decisions`：只读候选、淘汰、建议和实际路线哈希。
- `shadow_comparisons`：实际结果与 Shadow 建议的非反事实比较。

这些表不会保存 API Key、Authorization Header、原始异常正文或完整实际路线内容。

## 运行前检查

1. 先访问 `GET /api/v1/experiments/policy`，确认默认开关和 Shadow 边界。
2. 使用 `ExperimentBudget` 注册实验总预算、Provider 预算、最大逻辑调用数和最大尝试数。
3. 通过环境变量提供 Adapter 配置所引用的密钥；不要把密钥写入模型目录、数据库或导出文件。
4. 首轮只使用文本任务，并把真实结果交给独立验收器或人工盲评。
5. 保留强模型基线、人工静态路线和 CostWeave Shadow 建议，避免只比较有利样本。

## 证据门

默认测试和测试 Transport 只产生 `E0-transport-fixture`，不能算作真实任务。完成 30～50 个方向性真实任务后，还必须检查：

- 每条记录具有完整任务、部署、版本、费用和结果归因；
- 费用可与账单或 Provider 回执核对；
- Shadow 干预数仍为 0；
- 密钥扫描为 0 命中；
- 样本不足和选择偏差被明确披露。

满足以上条件之前，不应进入 v0.5.6.4 的学习型预测或策略晋级。

## 回退

回退前先备份数据库。v0.5.6.2 不认识 migration 016，建议继续使用 v0.5.6.3 程序读取升级后的数据库；若必须运行旧程序，应恢复升级前备份，不要手工删除迁移记录或实验表。
