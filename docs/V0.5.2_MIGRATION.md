# CostWeave v0.5.2 升级说明

## 升级结果

v0.5.2 可以直接覆盖 v0.5.1 的程序文件并继续使用原运行数据库。首次启动会自动应用 migration 010，把 Runtime / Projection Schema 升级到 `v5.2`。模型目录格式和已有模型编辑、导入数据没有变化。

## 行为变化

- 新任务的规划模式由 `PlanningGovernor` 决定，不再使用 v0.5.1 的模式仿真结果。
- 每个规划回执新增 11 维难度向量、难度区间、六条候选路线、ExpectedLoss、VoD 和执行前升级说明。
- 低置信、高风险或本地容量不足会在执行前进入增强路线，并触发高级验收门。
- 简单任务在直接处理的预期损失处于最优路线 5% 以内时优先使用 `NO_DELEGATION`；MultiPlanner 和 Expert 都有额外硬门，不能只因理论成功率略高而自动启用。
- 角色匹配增加模式级推理下限和标准化价格惩罚；价格优势不能绕过能力门，高价优势也不能覆盖低风险路线的成本目标。
- v0.5.1 的 proposal receipt 仍作为合同兼容数据保留，但不代表真实并行模型已经被调用。

## API 兼容

- 既有 `GET /api/v1/planning/policy` 与 `GET /api/v1/runs/{id}/planning` 路径不变。
- `schema_version` 变为 `v0.5.2`。
- `PlanningDecision.simulated` 对 Governor 决策为 `false`。
- 新增字段只扩展响应，不删除 v0.5.1 字段。
- 默认 `paid_calls_enabled` 仍为 `false`。

## 数据与回滚

migration 010 只增加 `(run_id, kind, stream_revision)` 规划审计复合索引，不删除表、列或事件。v4.9 和 v5.1 Projection 仍可读取。

升级前仍建议使用运行库备份接口建立备份。可靠回滚方式是恢复升级前备份；不要让旧版本程序持续写入已经升级的数据库。

## 尚未实现

- v0.5.3 才会让 2～3 个 Planner 真正并行产生独立提案并进行一次受限裁决。
- v0.5.4 才会接入实时 Provider 价格、配额、队列、熔断和 deadline miss 预测。
- 当前本地分类器是可替换的确定性实现，不是已经用用户数据训练完成的学习模型。
