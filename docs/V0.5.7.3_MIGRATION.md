# CostWeave v0.5.7.3 升级说明

v0.5.7.3 可直接覆盖 v0.5.7.2。首次启动自动应用 migration 024，将 Runtime Schema 从 `v5.7.2` 升级为 `v5.7.3`；既有运行、Outcome、预测器、策略候选、离线回放和 Production-like Shadow 记录保持不变。

## 新增数据

migration 024 新增七类不可变记录：

- 签名策略清单；
- 晋级证据包；
- 分阶段证据门报告；
- 状态转换收据；
- 策略卡；
- 冻结/回滚收据；
- 注册表指针事件。

所有表都拒绝更新和删除。策略状态由初始 `draft` 与不可变转换事件推导，不使用可被静默覆盖的状态列。转换收据带连续修订号，写入时使用事务重新核对当前状态，可拒绝过期并发写入。

## 签名密钥

`PolicyManifest.create()` 和 `PolicyRegistryStore.record_manifest()` 要求至少 32 字节的 HMAC-SHA256 密钥。数据库仅保存 `signer_key_id`、内容哈希和签名，不保存密钥。调用方应从密钥管理系统或进程环境提供密钥并自行轮换；示例和测试密钥不得用于真实环境。

## 状态与证据门

允许的主路径为：

```text
draft → evaluated → shadow → canary → active
  └──────────────→ frozen → retired
```

不能跳级。进入 `canary`、`active` 或 `retired` 需要显式批准标识。进入每个主路径状态前，必须保存与同一策略版本、同一证据包绑定的合格门报告。

最低证据要求：

| 阶段 | 最低等级 | 最低案例数 | 额外要求 |
|---|---:|---:|---|
| evaluated | E2 | 30 | 真实来源、独立评测、离线回放通过 |
| shadow | E3 | 30 | Production-like Shadow 通过，P95 开销不高于 10% |
| canary | E3 | 200 | 所有正式质量、CPS、时延、风险和硬违规门通过 |
| active | E4 | 1,000 | Canary 证据存在，所有正式门再次通过 |

正式门沿用路线图定义：最终成功率非劣界 `≥ -1pp`、高风险成功率不下降、CPS 改善 95% CI 下界严格 `>15%`、并行 P95 改善 `≥15%`、Handoff 返工率严格 `<2%`，硬预算、权限、并发和调用次数违规均为 0。MultiPlanner 默认启用还需困难集成功率提高 `≥5pp` 或 Routing Regret 改善 `≥15%`。

## 重要边界

v0.5.7.3 的 `active` 只表示注册表中的已审查资产和默认回滚指针，不表示真实运行路由已激活。所有清单、门报告、转换、策略卡和回滚收据都固定：

```text
routing_authority = false
runtime_route_changed = false
runtime_activation_executed = false
execution_side_effect_count = 0
```

真正的有界 Canary、运行时策略快照切换和自动回滚属于 v0.5.7.4。

## 兼容性检查

升级后可检查：

- `GET /api/health` 返回版本 `0.5.7.3`、Runtime Schema `v5.7.3` 和 24 项 migration；
- `GET /api/v1/policies/registry` 返回状态机、精确门槛、当前注册表指针与零运行时干预计数；
- 原有 `/api/v1/shadow/policy`、`/api/v1/replay/policy` 和 `/api/v1/predictors/policy` 保持兼容。
