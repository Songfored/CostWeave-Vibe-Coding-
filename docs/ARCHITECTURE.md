# CostWeave v0.2 架构说明

CostWeave v0.2 是一个离线决策型 Agent Runtime 原型。它把“理解、拆分、选择模型、并行执行、逐步验收、失败升级”分成可观察且可测试的控制面。

## 1. 任务画像

本地规划器不会立刻调用模型，而是先从目标中提取：

- 任务类型与跨领域数量
- 1–10 级难度
- 歧义与不确定性
- 普通、提升或高风险等级
- 是否依赖最新外部事实
- 是否需要搜索、代码执行或函数调用
- 文本、图像等输入模态
- 预计输入与输出 Token

难度过高或判断置信度不足时，DAG 会先增加 `planning-escalation`，让高级模型复核任务图，再释放专业分支。

## 2. 结构化分工

每个专业分支都有完整任务合同和独立 `verify-*` 节点。专业分支之间尽量并行，验证节点也可以在各自上游完成后并行启动。风险审查只接受通过验证的成果，最终汇总只依赖风险审查。

任务合同包含目标、包含/排除范围、依赖、能力、工具、模态、风险、Token 估计、输出 Schema、验收标准，以及实际发送给模型的最小充分提示词。

## 3. 约束优先的模型路由

路由不是从固定角色中随机选择。每个模型包含版本化事实：厂商、型号、价格、上下文、输出上限、模态、工具、来源和核验日期；另有 CostWeave 可校准的能力、推理、速度和可靠性先验。

路由步骤：

1. 硬过滤：可路由状态、货币、上下文、输出、模态、工具、时效检索和最低能力。
2. 成功率估计：能力均值与短板、可靠性、推理难度差、工具、上下文和高风险适配。
3. 质量门槛：没有候选达到门槛时明确失败，不偷偷降级。
4. 成本估计：输入与输出 Token 分别乘以官方标价。
5. 组合优化：先为全 DAG 求最低成本可行组合。
6. 预算升级：按预测质量增益/额外成本排序投入剩余预算；极速模式额外奖励速度。

## 4. 并行与预算守卫

调度器只在全部依赖通过验收后启动节点。启动前预留在途节点费用，避免并发完成后才发现预算已经超支。峰值并发受用户参数限制。

## 5. 验收与重规划

结果至少经过 Schema、合同字段、非空摘要、证据和置信度校验。验证、风险和安全节点使用更高级验收层级；高难或高风险节点标记为高级验收。

适配器异常或结果失败时：

1. 降低全局成功率估计。
2. 计算失败节点的下游影响范围。
3. 保留不依赖失败节点的已验收成果。
4. 用更高难度合同创建恢复节点。
5. 对所有剩余节点按剩余预算重新计算模型组合。
6. 新计划通过 DAG 校验后恢复并行执行。

## 6. 当前边界

执行器仍为模拟器。v0.2 证明的是决策、预算、并行、验收和恢复机制，而不是真实模型答案质量。生产版本还需要适配器、密钥隔离、真实 Token 计费、限流、观测、评测集与在线校准。
