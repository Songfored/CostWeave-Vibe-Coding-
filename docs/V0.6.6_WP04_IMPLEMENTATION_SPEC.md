# v0.6.6 V066-WP04 implementation specification

## Scope

WP04 adds a capacity-aware local OpenAI-compatible boundary for Ollama- and
vLLM-style loopback endpoints. It reuses the provider-neutral request,
response, streaming and cancellation contract from WP01/WP02 and adds a
separate, explicit pre-execution admission layer.

The implementation is `costweave.gateway_local` and is exported through
`costweave.adapters`.

## Admission sequence

1. Validate the endpoint as a loopback URL with no credentials, query or
   fragment using the WP02 validator.
2. Require `OpenAICompatibleRuntimePolicy(network_enabled=True)`.
3. Require `LocalEndpointAdmissionPolicy(capacity_admission_enabled=True)`.
4. Read a fresh `LocalCapacitySnapshot` from the caller-injected
   `LocalCapacityProbe` immediately before synchronous provider I/O or when a
   streaming iterator actually starts provider I/O.
5. Reject missing, invalid, incomplete or stale telemetry before any transport
   operation.
6. Reject insufficient slots, excessive queue depth or excessive estimated
   wait according to the explicit policy limits.
7. Only after all hard constraints pass, delegate the request to the WP02
   OpenAI-compatible backend.

## Capacity contract

The normalized snapshot contains:

- `queue_depth` and `queue_limit`;
- `available_slots`;
- `estimated_wait_ms`;
- `telemetry_age_ms`;
- immutable `snapshot_id`, `source` and `captured_at`.

Every numeric field is bounded. Missing fields are represented by `null` and
are always rejected; complete telemetry is a non-disableable safety invariant.
Freshness uses the greater of the reported `telemetry_age_ms` and the age
derived from `captured_at` using the local trusted clock. Snapshots too far in
the future are rejected. A probe that raises or returns an object other than
`LocalCapacitySnapshot` is rejected without retaining its exception text in
the exported error chain.

## Safety rules

- Network and capacity admission are both default-off.
- Missing telemetry fails closed; no optimistic zero queue or infinite capacity
  assumption is made.
- `require_complete_telemetry` is retained for schema compatibility but cannot
  be set to `false`.
- The endpoint remains loopback-only. Remote URLs, credentials, query strings
  and fragments remain invalid.
- The probe is caller-owned and injected. WP04 does not discover ports,
  import a metrics SDK, read credentials or open an extra telemetry socket.
- The admission decision is retained in a bounded in-memory history for local
  observability and is not presented as production telemetry.
- The public policy exposes the evidence level and explicit default-off state.

## Explicit non-goals

WP04 does not implement Ollama/vLLM-specific metrics scraping, GPU discovery,
distributed capacity, queue reservation, dynamic autoscaling, OpenTelemetry,
remote providers, paid calls, Shadow traffic or production readiness. A real
probe and a separately authorized local endpoint are required for any
integration beyond the E0 static fixture.

## Exit evidence

The work package is complete when:

- default network/capacity policies produce zero transport calls;
- missing, stale, incomplete and over-capacity snapshots fail before transport;
- a complete admitted snapshot reaches the existing OpenAI-compatible fake
  contract;
- streaming performs the same capacity check;
- delayed streaming consumption is checked when provider I/O begins;
- stale/future `captured_at` values cannot be masked by a smaller reported age;
- probe errors and invalid values fail closed without leakage;
- the direct WP02/WP03/release suites remain green;
- the release manifest includes local endpoint and local capacity default-off
  gates.
