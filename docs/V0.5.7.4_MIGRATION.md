# CostWeave v0.5.7.4 升级说明

v0.5.7.4 可直接覆盖 v0.5.7.3。首次启动自动应用 migration 025，将 Runtime Schema 从 `v5.7.3` 升级为 `v5.7.4`，运行投影从 `v5.5` 升级为 `v5.6`。既有运行、Artifact、Outcome、回放、Shadow、策略候选和注册表记录保持不变。

## 默认行为

升级后 Canary 仍然关闭：

```text
COSTWEAVE_CANARY_ENABLED=0
```

关闭状态不会创建部署、改变任务策略或产生外部调用。`GET /api/v1/canary/policy` 会明确返回 `runtime_enabled=false`。

## 启用前置条件

设置 `COSTWEAVE_CANARY_ENABLED=1` 只打开部署入口，不会绕过以下条件：

1. 候选必须是已签名且处于注册表 `canary` 状态的精确版本；
2. 回滚目标必须是当前注册表指针指向的 `active` 稳定版本；
3. 候选必须存在已持久化且通过的 Canary 门报告；
4. 部署必须提供新的人工批准标识、解释、版本和回滚目标；
5. 允许/禁止任务族必须与签名清单完全一致；
6. 部署固定从 5% 开始，不能直接指定更高阶段；
7. 真实 Adapter、付费调用和密钥仍受各自的独立开关与预算控制。

## 数据库变化

migration 025 新增：

- `canary_deployments`
- `canary_runtime_pointer_events`
- `canary_run_assignments`
- `canary_observation_windows`
- `canary_stage_decisions`

五类表均为追加式记录，数据库触发器拒绝更新和删除。旧运行投影没有 `policy_snapshot` 时按 `None` 兼容读取；新运行只有在存在部署上下文时才写入快照。

## 回滚到旧程序

代码可以退回 v0.5.7.3，但旧程序不识别 migration 025 的运行时 Canary 状态，也不会消费 `policy_snapshot`。安全回退步骤是先让当前部署形成 `rolled_back` 指针，再停止 v0.5.7.4 进程并备份 SQLite；不要在仍有候选曝光时直接用旧版本接管。
