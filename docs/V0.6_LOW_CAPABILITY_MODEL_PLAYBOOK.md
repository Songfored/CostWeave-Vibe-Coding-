# CostWeave v0.6 低能力模型施工总手册

版本：Revision 1  
适用基线：CostWeave v0.5.8.4  
目标版本：v0.6.0～v0.6.7  
最后校对：2026-08-09

## 0. 本手册的用途

本手册专门用于把 CostWeave 交给理解能力、规划能力和长上下文能力较弱的模型实施。它不是建议清单，而是施工顺序与验收合同。

执行模型必须遵守以下解释顺序：

1. 当前用户明确要求；
2. 本手册的安全规则和停止条件；
3. 当前版本的精确实施规格；
4. `V0.6_DECISION_INTELLIGENCE_ARCHITECTURE.md`；
5. `V0.6_COMPETITIVE_UPGRADE_PLAN.md`；
6. 历史路线与历史版本文档。

如果文件之间冲突，禁止自行猜测。停止实施，输出冲突位置、两种解释及影响范围。

## 1. 绝对施工规则

以下规则适用于每个工作包，不得省略。

### 1.1 一次只做一个原子工作包

- 不得同时实现两个编号工作包；
- 不得顺手重构无关文件；
- 不得提前实现后续版本接口；
- 当前工作包测试未通过，不得进入下一工作包；
- 当前版本退出门未全部通过，不得修改下一版本号。

### 1.2 修改前必须读取

每个工作包开始前：

1. 读取工作包列出的全部输入文件；
2. 用 `rg` 查找将修改的符号和所有调用点；
3. 记录修改前测试命令和结果；
4. 确认允许修改的文件列表；
5. 如果实际代码与手册描述不一致，停止并报告，不得凭印象改写。

### 1.3 修改方法

- 文本文件使用 `apply_patch`；
- 不使用脚本批量重写源码；
- 不执行 `git reset --hard`、`git checkout --` 或递归删除；
- 不删除、跳过、重命名已有测试来制造通过；
- 不放宽验证条件来让坏输入通过；
- 不把测试中的期望值改成当前错误输出；
- 不引入网络调用，除非当前版本明确授权；
- 不读取或写入真实密钥；
- 不新增依赖，除非工作包明确列出依赖和回退路径。

### 1.4 每次修改后的固定动作

1. 运行当前工作包新增测试；
2. 运行直接受影响的历史测试模块；
3. 检查是否生成 `__pycache__`、临时数据库或输出垃圾；
4. 记录修改文件、测试数、失败数和已知边界；
5. 只有全部通过才将工作包标记完成。

### 1.5 禁止伪造智能

- 模拟数据只能标为 E0/E1，不能写成真实效果；
- 厂商资料只能作为先验，不是成功标签；
- 模型自报置信度不能直接成为 `CapabilityPosterior`；
- 没有选择概率的数据不能用于无偏 IPS/DR 结论；
- 没有独立验收的成功不能进入训练标签；
- 没有统一 Tournament 的比较不能写“超过 Claude”或“超过竞品”；
- 测试数量、代码行数和页面数量不能作为智能提升证据。

## 3. 开工前的基线冻结

执行以下步骤，顺序不得改变。

确认当前目录包含：

- `pyproject.toml`；
- `costweave/`；
- `tests/`；
- `docs/`；
- `README.md`。

任一文件缺失则停止。

### BASE-02：记录版本

检查：

- `pyproject.toml` 为 `0.5.8.4`；
- `costweave/__init__.py` 为 `0.5.8.4`；
- `event_store.RUNTIME_SCHEMA_VERSION` 为 `v5.8.4`；
- migration 数量为 29；
- 最新 migration 为 `029_release_attestations.sql`。

如果不是上述基线，停止并重新生成实施差异，不得继续套用本手册。

### BASE-03：完整回归

运行：

```bash
python -B tests/run_isolated.py
```

预期基线为 706 项测试、0 失败。测试数可以因后续合法提交增加，但开始施工前不得存在失败。

### BASE-04：稳定版复现

运行：

```bash
python -B -m costweave.release_cli --pretty
```

必须满足：

- 命令退出码 0；
- 7/7 稳定门通过；
- 外部调用尝试为 0；
- EventLog 重放一致；
- 逻辑备份一致。

### BASE-05：生成基线记录

记录以下信息到当前任务回复，不在仓库创建临时文件：

- Python 版本；
- 当前 CostWeave 版本；
- 测试总数；
- 完整测试耗时；
- 稳定门数量；
- 当前目录是否为 Git 仓库；
- 已存在的未提交或用户修改文件。

如果目录不是 Git 仓库，不得擅自初始化 Git。

## 4. 跨版本不变量

每个版本必须保持以下事实。

### 4.1 单一事实源

- EventStore 是运行事实源；
- 新持久化模块使用同一个 Runtime SQLite 文件；
- 不建立第二个运行数据库；
- 事实表只追加，不静默覆盖；
- 相同 ID/幂等键写入不同内容必须拒绝；
- 投影或报告可以重建，但原始证据不可修改。

### 4.2 确定性

- JSON 使用 UTF-8、排序键、紧凑分隔符和 `allow_nan=False`；
- Identity Hash 不包含当前时间、随机临时路径或字典遍历顺序；
- 同一输入、策略、数据集、价格快照和随机种子产生同一报告 Hash；
- Bootstrap、随机基线和搜索器必须显式保存 Seed；
- 不能用 Python 内置 `hash()` 生成持久 ID。

### 4.3 输入防御

- 拒绝 NaN、Infinity 和非 JSON 值；
- 拒绝未知字段；
- 拒绝重复 ID、重复依赖和循环 DAG；
- 文本、数组、文件和记录数都有上限；
- 外部路径必须是用户明确提供的本地文件；
- 导入器不得执行输入文件中的代码；
- 导入数据只读，原始 Hash 与转换 Hash 都记录。

### 4.4 项目隔离

- 所有持久化决策和报告包含 `project_id`；
- 查询必须按 `project_id` 过滤；
- 项目 ID 使用现有 `normalize_project_id`；
- 不得把一个项目的 Trace、Artifact、缓存或 Outcome 返回给另一个项目。

### 4.5 权限与能力分离

- 模型更强不代表权限更高；
- MetaController 不能扩大工具、网络、数据或副作用权限；
- Planner 只能提出策略，不能绕开 ControlKernel 执行；
- Benchmark 和 Shadow 默认无副作用；
- 任何真实/付费调用仍需要现有 Runtime Policy 和预算门。

### 4.6 版本更新

每个正式版本只允许一次完整版本更新。不得全仓库盲目替换历史文档版本。

需要检查的当前版本位置：

- `pyproject.toml`；
- `costweave/__init__.py`；
- `costweave/server.py`；
- 当前版本模块 Docstring；
- `event_store.RUNTIME_SCHEMA_VERSION`；
- `release_readiness` 的当前 Runtime/Migration 门；
- `runtime_maintenance` 当前 Runtime Schema；
- `outcome_store` 当前 Runtime 标识；
- 只断言当前 Runtime 的测试。

历史模块自己的 Schema，如 `v0.5.7.3` Policy Registry，不得因为产品版本变化而修改。

## 6. v0.6.1 施工顺序：Rational MetaController

只有 v0.6.0 全部退出门通过后执行。

### V061-WP01：冻结 MetaDecision 合同

实现四种动作：

- `FAST`；
- `DELIBERATE`；
- `PROBE`；
- `EXPERT`。

合同必须包含：输入 Belief Hash、动作、预算、原因码、效用区间、信息价值估计、证据、策略版本和时间。未知动作或负预算必须拒绝。

### V061-WP02：规划预算账本

分别限制：

- 美元；
- 输入 Token；
- 输出 Token；
- 墙钟时间；
- Planner/Judge/Probe 调用数。

每次保留预算使用原子事务；失败释放保留；已发生费用不可回滚。预算不足时返回明确拒绝，不得静默降级。

### V061-WP03：快速路径

快速路径必须同时满足：

- 硬约束均可满足；
- 风险低；
- OOD 低于阈值；
- 证据未过期；
- 最佳策略的保守效用下界高于第二名上界或达到安全边际；
- 不需要不可逆副作用审批。

任一条件不满足，快速路径不得执行。

### V061-WP04：Expected Value of Computation

实现：

```text
EVC = expected_regret_reduction
    - planning_money_cost
    - latency_penalty
    - coordination_penalty
```

所有项使用相同 Utility 单位。EVC 小于或等于 0 时禁止增加 Planner。缺少证据时使用保守下界，不得自动设为正数。

### V061-WP05：Active Probe

Probe 必须：

- 无外部副作用；
- 可独立验收；
- 成本上限明确；
- 只回答会改变策略选择的问题；
- 结果进入新 Belief，而不是直接当最终成果。

测试 Probe 失败、无信息、成本过高和结果冲突四种情况。

### V061-WP06：自适应 Planner 委员会

成员按边际信息价值和失败相关性排序。不得固定“总是三个 Planner”。每加入一个成员后重新计算停止条件。达到预算、共识可信区间或 EVC≤0 时停止。

### V061-WP07：专家升级

至少覆盖：高风险、OOD、能力证据过期、效用区间重叠、目标冲突、本地容量不足。升级只移交决策，不扩大权限。

### V061-WP08：消融与退出门

比较：无 MetaController、固定 Planner、固定 MultiPlanner、Rational MetaController。必须报告规划成本比例、Decision Regret、CPS、P95 和覆盖率。没有净收益则不得晋级。

## 7. v0.6.2 施工顺序：Capability Evidence Graph

### V062-WP01：图 Schema

节点类型固定为：TaskFamily、ModelRevision、ReasoningTier、Tool、Modality、ProviderDeployment、Validator。边只保存可审计的条件证据。

### V062-WP02：证据摄取

只接受：公共基准、独立 Outcome、硬验收、人工盲评和受控实验。保存来源、版本、时间、样本数、选择机制和证据等级。

### V062-WP03：分层先验与冷启动

新模型使用模型族、厂商元数据和公开基准生成宽区间先验。厂商资料不得把证据等级提升到真实 Outcome。测试无数据、少量数据和数据冲突。

### V062-WP04：条件后验

分别预测：成功、成本、延迟、重试、升级和返工。不得把不同任务族或不同模型版本无条件合并。

### V062-WP05：失败相关性

记录模型—模型、模型—Validator 的共同失败。样本不足时标为未知，不得默认为独立。

### V062-WP06：校准与拒答

实现校准集隔离、可靠性图数据、ECE/Brier 和风险覆盖。低覆盖、OOD、版本漂移或证据过期返回 `ABSTAIN/ESCALATE`。

### V062-WP07：漂移

监测任务分布、模型版本、价格、延迟和错误率。漂移触发冻结候选策略，不直接重新训练生产策略。

### V062-WP08：L1 Tournament

与 strong-only、cheap-only、random、static、RouteLLM 类和 LLMRouter 类基线比较。未达到预注册质量非劣与成本门，只能保留 Shadow。

## 8. v0.6.3 施工顺序：Joint Strategy Search

### V063-WP01：候选工厂

候选必须来自四路：安全基线、历史检索、Planner 提案、局部变换。`NO_DELEGATION` 和强模型端到端不得缺席。

### V063-WP02：硬约束剪枝

先检查权限、工具、数据驻留、预算、上下文、模态、容量和截止时间。被拒候选保存原因，不能进入软评分。

### V063-WP03：联合策略评分

同时评分管理、分解、模型、工具、并发、Handoff、Validator 和 Recovery。使用分布与尾部风险，不得简单相乘全部节点平均成功率。

### V063-WP04：Anytime Search

先实现确定性 Beam Search；再分别以插件加入 Successive Halving、LUCB/Bayesian。每个搜索器有状态数、时间、内存和调用上限。

### V063-WP05：Pareto 与相关失败

保留质量—成本—时间非支配集；委员会和 Validator 组合计入共同失败，不得把高度相关的两个模型当成双倍保险。

### V063-WP06：Handoff Compiler

实现 Coverage、Contradiction、Authority、Information Loss 四道门。使用 Artifact 引用和差量上下文，禁止重复搬运全部历史。

### V063-WP07：Oracle 与差分测试

小问题使用精确枚举 Oracle，与搜索器逐例比较；大问题报告最优界或未知差距。随机生成小 DAG 做差分测试。

### V063-WP08：退出门

相同搜索预算下优于单节点贪心和固定模型组合。任何算法若只提高分数但使总 CPS、P95 或风险变差，不得晋级。

## 9. v0.6.4 施工顺序：执行中更新与恢复

### V064-WP01：Progress Belief

保存当前成功分布、已验收 Artifact、未验收节点、关键路径、剩余预算、资源状态、污染范围和策略切换成本。

### V064-WP02：更新触发器

只在明确事件后更新：节点结果、里程碑、Validator 结果、预算偏差、工具失败、Provider 状态、用户约束变化和假设被否定。

### V064-WP03：独立 Validator

确定性验收优先；LLM Judge 必须记录家族相关性、版本和校准。执行模型不得给自己最终通过。

### V064-WP04：污染传播

失败只污染消费该 Artifact 的下游节点。已经独立验收且不依赖污染 Artifact 的成果继续复用。

### V064-WP05：恢复动作

固定动作集：CONTINUE、RETRY_NODE、SWITCH_MODEL、REQUEST_MISSING_INFO、REPLAN_SUBGRAPH、FULL_REPLAN、STOP_AND_RETURN_PARTIAL。未知动作拒绝。

### V064-WP06：经济比较

未来动作不计算沉没成本，但计算剩余预算、切换成本、可复用价值、污染和尾部风险。

### V064-WP07：故障与动态场景

覆盖限流、宕机、OOM、超时、错误账单、Validator 误判、价格突变、队列突增、期限缩短和用户新约束。

### V064-WP08：退出门

相对固定重试和全部重做，Recovery Advantage 为正；权限、预算和重复副作用为 0。

## 10. v0.6.5 施工顺序：信用分配与安全学习

### V065-WP01：信用组件固定

只允许 decomposition、routing、handoff、execution、validation、recovery 六类。新增类别必须升级 Schema。

### V065-WP02：证据优先级

确定性定位 > 单节点反事实 > 匹配/分层估计 > IPS/DR > LLM 归因。低等级证据不能覆盖高等级证据。

### V065-WP03：选择概率

所有可学习决策保存完整候选集和选择概率。确定性策略保存 1.0。概率和必须为 1；未记录则标记不可用于 IPS/DR。

### V065-WP04：Counterfactual Replay

只替换被比较组件，冻结其他输入、价格、模型输出和验收器。无法冻结时标记反事实不可识别。

### V065-WP05：IPS/DR

权重必须裁剪并报告有效样本量。支持率不足、权重爆炸或策略无重叠时拒绝结论。

### V065-WP06：候选策略

学习只生成候选 Capability、Router、Prompt 或 Recovery Policy。不得直接修改 Activated Policy。

### V065-WP07：晋级链

固定为 Offline Blind → Shadow → Canary → Activate。任一阶段失败回滚或拒绝。

### V065-WP08：数据删除和再训练

用户删除数据后，学习副本、索引和未来训练集都移除；已发布模型是否受影响必须记录，而不能声称自动遗忘。

## 11. v0.6.6 施工顺序：真实互操作与 Shadow

### V066-WP01：Gateway Backend 合同

统一请求、流事件、结构化输出、工具、用量、账单、错误、取消和 Provider Request ID。核心决策不得依赖具体 Provider 字段。

### V066-WP02：OpenAI-compatible

先通过本地 Fake Server 契约测试，再接用户明确配置的本地端点。默认仍禁用网络。

### V066-WP03：LiteLLM 互操作

把 LiteLLM 视为外部 Gateway，不复制其 Provider 实现。验证模型名称、错误分类、用量和成本回执映射。

### V066-WP04：本地端点

支持 Ollama/vLLM 风格 OpenAI-compatible 端点。首次执行前读取队列/容量；遥测缺失时保守准入。

### V066-WP05：OpenTelemetry

## 14. 失败停止矩阵

| 情况 | 必须动作 | 禁止动作 |
|---|---|---|
| 基线已有失败 | 停止并报告 | 在失败基线上继续开发 |
| 规格与代码冲突 | 列出冲突并停止 | 自选一种理解继续 |
| Migration Hash 不匹配 | 停止，保留数据库 | 修改已发布 Migration |
| 新旧 ID 同内容不一致 | 拒绝写入并测试 | 覆盖旧记录 |
| Hash 两次运行不同 | 找到非确定字段 | 在测试中忽略 Hash |
| 导入字段缺失 | 返回结构化错误 | 用 0 或空字符串伪造 |
| 置信区间无法计算 | 标记不可声明 | 用点估计宣布胜出 |
| Provider 账单无法对账 | 排除商业证据 | 使用内部估算替代真实账单 |
| 需要真实密钥 | 请求用户明确配置 | 搜索磁盘或日志中的密钥 |
| 测试变慢或挂起 | 定位当前工作包 | 扩大全局超时掩盖死锁 |
| 需要修改无关文件 | 停止并扩大任务卡 | 顺手重构 |

## 18. 最终原则

低能力模型最容易造成的错误不是语法错误，而是：

- 把未知数据填成 0；
- 把模拟结果当真实结果；
- 把模型自信当成功概率；
- 把更多 Planner 当更智能；
- 把并发当免费；
- 把最终成功错误归因给全部组件；
- 为通过测试修改门槛；
- 在版本间复制出第二套事实源。

本手册的核心目的，是让这些错误在合同、持久化、测试、晋级和发布五个层面都无法静默发生。
