# CostWeave v0.5.5 升级说明

v0.5.5 可直接覆盖 v0.5.4 程序文件，并继续使用原运行数据库。首次启动会自动应用 migration 013，将 Runtime / Projection Schema 升级为 `v5.5`。

## 数据库变化

- `messages.contract_hash`：保存 WorkOrder 的确定性合同摘要。
- `messages.preflight_json`：保存接收模型执行前的工具、模态、容量、Artifact、Schema、权限与审批检查。
- `failure_records.recovery_receipt_json`：保存 Pcomplete、污染传播、恢复门禁、升级证据、预计成本和影响范围。
- 新增运行交接查询索引。
- 旧 `v5.4`、`v5.3`、`v5.2`、`v5.1` 与 `v4.9` 投影仍可读取。

## 行为变化

- 每个持久任务在执行前编译为 WorkOrder 和最小 Context Manifest。
- 接收方合同预检失败会在模型执行前拒绝节点，并按合同错误进入有界恢复。
- 运行投影新增 `handoff_history`、`completion_checkpoints`、`pollution_reports` 与 `global_replans`。
- 根假设失败最多允许一次全局重规划；普通节点升级不消耗这一次全局额度。
- 硬依赖与验证依赖传播失效，软依赖只标记可疑；无关已验收成果不会因“全局”二字被删除。
- 恢复节点不得扩大原任务工具或数据权限，不可逆替换需要新的审批。
- 新增 `GET /api/v1/runs/{id}/handoffs` 和 `GET /api/v1/runs/{id}/recovery`。

## 兼容与回退

设置 `COSTWEAVE_HANDOFF_INTELLIGENCE=0` 可停止新 WorkOrder 预检、Pcomplete 与污染感知门禁，保留 v0.5.4 兼容行为。该开关不放宽既有 Success Contract、权限或 Artifact 校验。

回退程序前应先备份运行数据库。v0.5.4 不认识 `v5.5` 投影和 migration 013 新字段，建议保留 v0.5.5 程序读取已经升级的数据库。模型目录格式无需降级。
