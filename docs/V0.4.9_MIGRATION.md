# CostWeave v0.4.9 升级说明

## 升级结果

v0.4.9 是 v0.4 发布列车的整合与加固版本。它不改变模型目录文件格式，也不删除 v0.3/v0.4 的旧读取接口；运行数据库会从 migration 007 自动升级到 008。

## 数据库升级

首次启动会：

1. 校验既有 migration 的校验和；
2. 创建 `event_integrity` 与 `media_commands`；
3. 为既有事件回填负载与信封 SHA-256；
4. 把运行 Schema 标记为 `v4.9`。

升级前可通过 `RuntimeMaintenance.create_backup()` 创建经过 `quick_check` 和外键检查的 SQLite 在线备份。恢复必须先停止 CostWeave，再显式调用 `restore_backup(..., runtime_closed=True)`；系统拒绝恢复哈希不匹配或健康检查失败的文件。

## API 兼容

- 新目录地址：`/api/v1/catalog` 及其子路径。
- 旧目录地址：继续可用，但返回 `Deprecation: true`、`Sunset` 和后继版本 `Link`。
- 新诊断地址：`GET /api/v1/system/diagnostics`。
- 新备份地址：`POST /api/v1/system/backups`，需要 JSON `{"confirm":"BACKUP"}` 和 `Idempotency-Key`。

## 回滚

代码可回滚到 v0.4.8，但 migration 008 不应手工删除。推荐流程：

1. 停止服务；
2. 使用升级前备份恢复数据库；
3. 安装 v0.4.8；
4. 启动后检查运行列表、事件数量和目录 revision。

若没有升级前备份，继续使用 v0.4.9；旧版本不了解事件完整性和媒体命令表，不能视为可靠回滚。

## 安全边界

服务仍只允许绑定 `127.0.0.1`、`localhost` 或 `::1`。这不是多用户认证系统。若未来开放远程访问，必须先增加身份认证、授权、TLS、跨用户隔离、速率限制和共享部署威胁模型。
