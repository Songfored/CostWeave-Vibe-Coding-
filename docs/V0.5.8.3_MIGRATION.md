# 升级到 CostWeave v0.5.8.3

v0.5.8.3 将 Runtime Schema 从 `v5.8.2` 升级为 `v5.8.3`，migration 数从 27 增至 28。Run Projection Schema 保持 `v5.6`。

## 升级步骤

1. 停止正在运行的 CostWeave 单机服务，并备份现有 SQLite 数据库。
2. 安装 v0.5.8.3 wheel 或源码包。
3. 使用原有 `COSTWEAVE_RUNTIME_DB` 启动；migration 028 会在同一迁移事务中创建新表与不可变触发器。
4. 打开 `/api/health`，确认 `runtime_schema` 为 `v5.8.3`、migration 为 28，事件完整性通过。
5. 打开 `/api/v1/resilience/status`，确认策略为默认关闭、项目范围正确。
6. 在复制的数据或测试环境完成一次备份、验证和恢复演练，再处理重要工作区。

## 数据变化

- 新增 `resilience_campaigns` 与 `resilience_observations`。
- 新增 `recovery_checkpoints_v0583` 与 `recovery_receipts_v0583`。
- 四张表均为追加式记录，更新和删除会被数据库触发器拒绝。
- 备份清单新增 `runtime_schema=v5.8.3` 与逻辑快照；旧清单不会被新版恢复流程静默接受。

## 兼容性与回滚

- 既有运行、任务、Artifact、账本、安全和证据数据不改写；旧 API 保持兼容。
- 应用代码可以回滚，但已迁移数据库不应直接交给旧版本写入。若必须回滚，请停止服务并恢复升级前的完整数据库备份。
- 恢复流程会拒绝缺少逻辑快照、文件哈希不符或逻辑根不一致的备份。

## 默认安全状态

故障注入和真实外部连接都默认关闭。韧性实验 API 只接受 E0/E1 offline/replay 记录，并拒绝真实、付费或外部调用声明。不要把本地夹具的时延和预测指标用于生产承诺。
