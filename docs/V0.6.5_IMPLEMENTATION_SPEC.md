# v0.6.5 implementation specification

## Contract order

1. Normalize project scope and reject unknown fields.
2. Validate the trace or logged decision.
3. Compute deterministic credit or the requested offline estimate.
4. Attach evidence level, origin, validation and choice-probability facts.
5. Persist the immutable object with a content hash and idempotency key.
6. Run hard promotion checks.
7. Return an advisory result with route_intervention=false.

## Learning gate

The estimator uses a capped importance weight of 20. The doubly robust
estimate combines the target-policy model prediction with the weighted
residual from the logged outcome. The approximate interval is a transparent
diagnostic, not a formal causal guarantee. Missing support, weak evidence,
non-independent validation, calibration failure or insufficient effective
sample size produces reason codes and usable_for_learning=false.

## Operational boundary

No endpoint invokes a model adapter. No endpoint writes the runtime route,
training corpus or Provider secret. Promotion assessment is a record of why a
candidate is frozen, shadow-eligible or rejected. This keeps the control plane
safe while allowing later real-data integrations to be audited.
