# v0.6.6 V066-WP03 implementation specification

## Scope

WP03 adds a provider-neutral LiteLLM interoperability boundary. LiteLLM is
treated as an external Gateway and is supplied through an injected
`LiteLLMCallTransport`. CostWeave does not import the LiteLLM SDK, resolve
provider credentials, persist secrets, or open a network connection here.

## Admission and mapping

1. Require `LiteLLMRuntimePolicy(gateway_enabled=True)` and an injected
   transport. The default path rejects before the transport is called.
2. Resolve an editable, bounded model-alias map into the LiteLLM model name.
   Resolve its billing mode as `free`, `paid` or `unknown`; missing entries are
   `unknown`, and both `paid` and `unknown` require explicit paid-call authority.
3. Map provider-neutral messages, tools, structured output, temperature and
   output-token limits into a bounded chat-completions payload.
4. Map model name, provider request ID, usage, cached tokens, reasoning tokens,
   structured output, HTTP error classes and optional `response_cost` into the
   v0.6.6 Gateway objects.
5. Treat streaming and provider cancellation as explicit deferred capabilities;
   do not claim support that the injected transport does not provide.

## Safety rules

- No LiteLLM package import is required by the core.
- No API key, Authorization header or provider secret is accepted by config.
- Gateway calls and paid calls are disabled by default.
- Paid/unknown-cost requests are rejected before transport unless both gateway
  and paid-call authority are enabled; explicitly free models remain usable
  with paid calls disabled.
- Provider error text is not copied into the core error message.
- Invalid model aliases, oversized payloads, malformed usage and malformed
  cost values fail closed.
- FakeLiteLLMServer is an in-process E0 fixture and is not production telemetry.
- Only explicit `LiteLLMTransportError` failures are retryable network errors;
  unclassified transport exceptions fail closed as non-retryable.

## Non-goals

Real LiteLLM SDK execution, remote-provider authorization, retry policy,
streaming, cancellation, OpenTelemetry and production Shadow remain later
work packages. This increment does not support model-quality or cost-saving
claims.
