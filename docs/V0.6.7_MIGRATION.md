# CostWeave v0.6.7 迁移说明

## 用户可见变化

- 启动服务器后必须打开终端打印的完整 `#session=...` 地址；
- 直接请求 API 时必须发送 `X-CostWeave-Session`，也可使用 Bearer 形式；
- 非回环 Host、不可信 Origin、撤销项目和驻留域不匹配会更早失败；
- 风险 Prompt 不再接受只满足格式的 approval ID；
- 并发超限时可能收到 503，而不是继续无限创建线程。

## 开发者迁移

- 新 HTTP 路由必须先获得 `RequestSecurityContextV1`，不得信任裸项目头；
- 新外部适配器必须通过 `ExternalCallAuthorityV1` 获得并消费一次性 capability，不得直接调用 transport；
- Provider 响应必须在解析、哈希、Trace 和持久化前经过 authority 输出检查；
- 模糊账单、side-effect replay、秘密命中和 peer 不匹配必须失败关闭；
- 新项目资源读取必须同时使用项目活动状态和驻留域。

## 数据库

无新迁移。现有 35 个迁移和运行时 Schema v6.5 保持兼容。

## 回退

如必须回退到 v0.6.6，先停止服务并保留数据库备份。不得通过关闭会话认证、审批校验、秘密检查、预算冻结、全局幂等或 peer 固定来“兼容”旧调用方；这些控制属于不可降级安全边界。

## 发布限制

独立标准复扫未完成前，v0.6.7 只能作为候选版使用，不能标记为安全正式版。
