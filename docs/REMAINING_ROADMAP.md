## 1. 为什么调整后续排期

v0.5.1～v0.5.5 已经建立了两层规划治理、跨 Provider 资源建模、任务 DAG、结构化交接、成本账本、结果验收、失败恢复和审计回执。这些能力证明了控制平面可以运行，但尚未证明以下商业命题：

- CostWeave 比人工分流更准确；
- CostWeave 比全程使用强模型更便宜；
- 小模型产生的返工不会抵消调用成本优势；
- Psuccess、Pcomplete、成本和时延预测与真实结果一致；
- MultiPlanner 的收益大于多模型协调开销；
- 国内外、本地和云端模型的组合优于固定选择；
- 当前策略在真实高并发、限流和故障条件下仍然成立。

因此，下一阶段不再优先增加启发式规则，而是把 CostWeave 变成一个能接受真实实验检验、形成可信数据、校准预测并安全升级策略的系统。

## 3. 全阶段共同约束

### 3.1 不允许伪造“智能”

- 不使用模拟 Outcome 训练并宣称真实模型效果；
- 不把厂商宣传基准直接作为 CostWeave 的能力后验；
- 不把模型自报置信度当作成功标签；
- 不根据最近几条结果直接修改生产策略；
- 不以增加关键词和手工分数冒充学习型路由；
- 不在没有对照实验时宣传“降低 90%”或“十倍降本”。

### 3.2 默认不产生付费调用

- 全新安装的真实 Provider Adapter 必须默认关闭；
- 付费实验必须由用户显式启用；
- 每个实验、Provider、任务和整个批次都必须有硬成本上限；
- 密钥不得写入模型目录、任务合同、EventLog、Artifact 或 Outcome 数据；
- 失败、重试和超时仍计入真实总成本。

### 3.3 风险与权限不随模型能力升级

- 推理能力、推理档位和权限是独立维度；
- 高风险任务不参加随机探索；
- 不可逆操作必须使用新审批，历史审批不能自动继承；
- 策略升级不得扩大工具、数据、网络或外部副作用权限；
- Shadow 决策只能记录建议，不得偷偷改变执行路线。

### 3.4 管理深度保持两层

只允许：

```text
MetaPlanner
  └─ Planner 或 MultiPlanner
       └─ Executor / Validator
```

禁止递归创建更多 Planner 管理层。MultiPlanner 只有在预期信息价值大于协调成本时才能启用。

## 4. v0.5.6：真实评测、Shadow Learning 与数据驱动分流

### 4.1 v0.5.6 总目标

建立第一条从真实任务、真实模型调用和真实验收到可重放 Outcome 数据的完整链路，并用这些数据校准分流预测器。

v0.5.6 不以“模型更复杂”为成功，而以“预测能够被现实证伪、数据能够被复现、策略没有提前干预生产”为成功。

## 5. v0.5.6.1：Evaluation Protocol & Baseline Runner（已完成）

### 5.1 目标

冻结实验规则、任务格式、基线、盲评和成败标准。在不调用真实付费模型的情况下，先完成可重复的评测框架。

### 5.2 交付

- `ExperimentSpec`
  - 实验 ID、版本、随机种子；
  - 任务集版本；
  - 模型目录快照；
  - Prompt、策略和验收规则版本；
  - 成本、调用次数和时间上限；
  - 数据分组与盲评方案。
- `BenchmarkTask`
  - 用户目标；
  - Task Contract；
  - 硬约束、风险等级和禁止事项；
  - 预注册 Success Contract；
  - 允许的工具和数据；
  - 参考答案或独立验收方法。
- Baseline Runner
  - 全部任务使用最强可行模型；
  - 全部任务使用最低价可行模型；
  - 人工静态分配；
  - v0.4 固定规则；
  - v0.5 当前自适应策略。
- 盲评包
  - 隐藏模型、Provider、策略和价格身份；
  - 输出顺序随机化；
  - 评价者不能看到 CostWeave 的选择；
  - 硬验收与软质量评分分离。
- 结果比较器
  - 质量非劣；
  - CPS；
  - Time to Accepted Result；
  - 路由后悔值；
  - 规划和交接开销。
- 固定小型种子集
  - 30～50 个任务用于方向验证；
  - 至少覆盖代码、研究、写作、分析、长上下文、工具和多语言；
  - 该规模不得用于商业效果宣传。

### 5.3 验收

- 同一 `ExperimentSpec` 在相同输入下产生相同任务顺序和评测结构；
- 所有任务在执行前都存在 Success Contract；
- 评价者看不到路线身份；
- 硬失败不能被软评分覆盖；
- 所有基线使用同一预算、权限、工具和截止时间口径；
- 真实 Provider 调用数为 0；
- 实验输出可以导出为 JSONL 和 CSV；
- 数据结构可以被后续版本直接读取，无需第二套事实源。

### 5.4 停止条件

出现以下任一情况不得进入 v0.5.6.2：

- 同一输出在不同基线中使用了不同验收标准；
- 任务答案泄漏给执行模型；
- 评价者可以识别路线身份；
- 成本统计遗漏重试、验证、工具或返工；
- 任务集不能按项目和时间隔离。

### 5.5 实施结果

- 已冻结 `ExperimentSpec`、`BenchmarkTask`、`ExecutionTaskView`、共享资源上限和盲评合同；
- 已建立 35 个按项目隔离的 E0 种子任务，形成 15/10/10 的 train、calibration、test 分区；
- 已实现五组基线和 175 个观察项的确定性完整矩阵；
- 已实现 CPS、Time to Accepted Result、非劣差值、Routing Regret、规划与交接开销；
- 已实现未评分盲评包，模型、Provider、策略、价格和参考答案不会进入评审或执行负载；
- 已实现不可静默覆盖的 JSON、JSONL、CSV 导出，以及基于现有 `evaluation_runs` 的幂等持久化；
- 已验证真实 Provider 调用数为 0，证据等级固定为 `E0-simulated`，商业声明资格关闭；
- v0.5.6.1 退出门槛已通过，可以进入 v0.5.6.2，但不能据此宣称真实降本或真实模型效果。

## 6. v0.5.6.2：Outcome Dataset & Label Governance（已完成）

### 6.1 目标

让成功和失败数据能够安全、准确地参与后续改进，同时防止重复样本、错误标签、敏感信息和项目级数据泄漏。

### 6.2 交付

- `OutcomeRecord`
  - 匿名化任务特征和合同摘要；
  - 所有可行候选及淘汰原因；
  - 最终路线及选择概率；
  - 模型、部署、推理档位和 Adapter 版本；
  - Prompt、目录、策略、验收规则和代码版本；
  - 实际 Token、费用、时延、排队和工具成本；
  - 检查点、重试、升级、恢复和人工介入；
  - 最终验收、用户接受和延迟反馈；
  - 失败分类、根因和证据等级。
- 标签治理
  - 未经独立验收的输出不能成为成功标签；
  - 标签区分自动硬验收、独立模型验收、人工盲评和用户反馈；
  - 冲突标签保持并列，不强行覆盖；
  - 延迟反馈只能追加，不得修改历史原始事件。
- 数据隔离
  - 项目级、用户级和时间级分组；
  - 训练、校准和测试集按项目隔离；
  - 相似任务去重；
  - 敏感原文默认不进入学习库；
  - 支持脱敏、TTL、删除和用途限制。
- 数据质量报告
  - 缺失字段；
  - 标签覆盖率；
  - 重复率；
  - 项目泄漏检查；
  - 版本可追溯率；
  - 成本账本对账。
- 冻结学习机制
  - 数据不足；
  - 漂移异常；
  - 标签冲突过多；
  - 校准恶化；
  - 敏感数据治理失败时禁止训练和策略晋级。

### 6.3 验收

- Outcome 与原 Run、Task、Artifact、Message、Validation 和 Ledger 一一可追溯；
- 未验收结果进入成功标签的数量为 0；
- 同一项目不得同时进入训练集和测试集；
- 重复任务不会被当作独立样本放大；
- 删除请求能够删除学习副本，同时保留必要的不可变审计摘要；
- 旧策略可以使用绑定的原始版本重放；
- 数据质量未通过时，训练入口硬失败。

### 6.4 样本等级

| 阶段 | 样本量 | 可以做什么 | 不可以做什么 |
|---|---:|---|---|
| 种子验证 | 30～50 | 检查流程、字段和明显错误 | 宣传效果、训练正式路由器 |
| 内部验证 | 200～500 | 初步校准、比较任务族差异 | 宣称普适效果 |
| 正式基准 | 1000+ | 形成有置信区间的发布结论 | 推断未覆盖领域 |

正式基准至少覆盖 8 个任务族，每类原则上不少于 100 个任务。

### 6.5 实施结果

- 175 条路线观察生成 175 条匿名学习副本，并通过 35 个去重组和 `sample_weight` 折算为 35 个有效任务；
- 原始目标、项目/用户/任务标识、参考答案、输出正文和证据引用不进入学习副本；
- 标签证据支持自动硬验收、独立模型、人工盲评、用户反馈和系统终态；未经独立验收的正向反馈保持未标注；
- 冲突标签并列，延迟反馈追加，TTL 与删除留下无正文审计摘要；
- 项目泄漏、重复观察、敏感内容、版本缺失和成本不对账属于治理硬失败；
- E0、有效样本仅 35、候选路线集合不完整，因此 `training_allowed=false`，训练入口按设计硬失败；
- migration 015、Runtime Schema `v5.6.2`、治理 API、不可变导出与专项测试已完成；
- 本版通过的是治理机制验收，不是实际模型效果或降本验收。

## 7. v0.5.6.3：Experimental Real Adapters & Shadow Router（工程完成，证据门待通过）

### 7.1 目标

接入最小范围的真实模型执行能力，同时让新路由器只提出建议、不改变实际基线路线，从而低风险采集第一批现实数据。

### 7.2 交付

- 实验型 Adapter
  - OpenAI-compatible HTTP Adapter；
  - Local HTTP Adapter；
  - Provider 特定差异通过插件配置，不写入核心路由；
  - 文本能力先行，图片、视频和语音仍保持关闭；
  - 统一 Token、费用、延迟、错误和限流回执。
- 密钥边界
  - 只从环境或外部 Secret Provider 读取；
  - 日志和异常自动脱敏；
  - 不允许密钥进入 SQLite、导出文件或页面。
- 付费保护
  - 全局显式开关；
  - 每 Provider 和每实验硬上限；
  - 请求前预估；
  - 达到上限立即停止，不自动更换到更贵模型；
  - 重试计入预算。
- Shadow Router
  - 为每个任务生成建议路线；
  - 保存候选、预测、淘汰原因和建议选择；
  - 实际执行继续使用预注册基线；
  - Shadow 建议不得影响 Prompt、工具、预算或执行顺序；
  - 实验结束后比较建议路线与实际结果。
- 真实遥测
  - 输入/输出 Token；
  - 缓存、批处理和推理档位；
  - 请求、排队和工具时延；
  - Provider 错误、限流与取消；
  - 实际账单或可核对费用。

### 7.3 第一批实验建议

- 先用本地模型和低价 API 验证链路；
- 每个任务仅执行必要基线，避免为了建立近似 oracle 无限重复；
- 强模型基线、人工路由和 CostWeave Shadow 建议必须同时保留；
- 中国、国际和本地模型使用同一 Provider-neutral 合同；
- 不在这一版自动切换生产路线。

### 7.4 验收

- 默认安装和默认测试产生 0 个外部调用；
- 没有显式开关和预算时，真实 Adapter 拒绝运行；
- 相同幂等键不会创建重复的外部逻辑调用；
- 每次外部调用都能和任务、部署、费用及结果关联；
- Shadow 推荐与实际执行严格隔离；
- EventLog、Outcome 和导出文件中不存在密钥；
- Provider 失败不会造成预算越界；
- 至少完成一轮 30～50 个任务的方向性真实实验，并明确标注样本不足。

### 7.5 实施结果

- 已实现 OpenAI-compatible HTTP 与 Local Loopback HTTP 文本适配器；厂商差异只存在于配置，不进入核心路由分支；
- 已实现实验/付费双开关、实验总预算、Provider 子预算、逻辑调用数、尝试数、WorkOrder 预算与重试最坏情况预留；
- 已实现调用级幂等、不可变终态回执、费用超预留冻结和失败分类；
- 已实现环境变量密钥读取，持久化与公开配置不含密钥、Authorization Header 或原始异常正文；
- 已实现 Token、费用、请求/排队时延、缓存、推理档位、限流、取消、重试和完整任务/部署归因；
- 已实现只读 Shadow Router，任务合同变更会硬失败，持久记录固定为 `advisory_only=true`、`intervention_count=0`；
- 已实现只记录实际结果、不虚构未执行路线效果的 Shadow Comparison；
- migration 016、Runtime Schema `v5.6.3`、策略 API 和 27 项新增回归已完成；全量基线为 481 项；

### 8.1 目标

使用通过治理的真实 Outcome，预测每个“任务节点 × 部署 × 推理档位 × Prompt × 工具组合”的结果分布，并对整张 DAG 进行组合优化。

### 8.2 预测对象

- 首次成功、修复成功、升级、人工介入和最终失败概率；
- 输入/输出 Token 分布；
- 直接模型、验证、工具、返工和协调成本；
- 执行与完成 P50/P95；
- deadline miss 概率；
- 本地容量、队列和显存风险；
- 分布外风险和预测区间。

### 8.3 模型策略

首版优先使用可解释方法：

- 分层 Beta/Binomial 后验；
- 带任务族和部署特征的逻辑回归；
- 分位数或保序成本/时延校准；
- Platt 或 Isotonic 概率校准；
- 冷启动时回退到任务族、模型族和全局先验；
- 样本不足时扩大区间，而不是输出伪精确概率。

在可解释方法通过基准前，不引入难以审计的大型路由神经网络。

### 8.4 全局路由目标

候选路线不再只比较单节点价格，而是最小化：

```text
Expected Total Loss
  = Direct Model Cost
  + Expected Validation Cost
  + Expected Tool Cost
  + Expected Handoff Cost
  + Expected Rework / Escalation Cost
  + Latency Loss
  + Failure Loss
  + Capacity and Deadline Risk
```

同时满足成功率下界、硬预算、截止时间、权限、数据驻留、工具、模态、容量、验证独立性和两层管理深度。

### 8.5 DAG 组合优化

v0.5.6.4.3 已把以下内容实现为离线建议层，但输入仍是 E0 规则先验，尚未获得真实效果资格，也没有接管正式路由：

- 允许在关键架构节点使用更强模型，降低多个下游节点返工；
- 显式计算交接和上下文搬运成本；
- 共享 Provider 配额和本地资源池容量；
- 计算关键路径而不是简单相加全部节点时延；
- 比较“少拆分强模型”与“多拆分便宜模型”；
- 识别模型组合之间的互补、冲突和验证相关性；
- 高风险验证者不得与执行者共享同一失败来源。

当前求解器是有界确定性 Beam Search；只在搜索未截断且未发生 Beam 剪枝时声明已证明最优。后续真实校准版必须与精确小图求解器和预注册基线进行差分验证，不能默认把启发式结果当作全局最优。

v0.5.6.4.4 已完成精确小图差分验证：默认最多 10 个节点、100,000 个组合，界外不作最优声明。敏感性目前只报告离散测试点，尚未实现连续参数区间、联合分布不确定性或真实概率传播。

### 8.6 验收

- 测试集按项目与时间隔离；
- 预测使用的数据版本和特征可重放；
- 整体 Psuccess `ECE ≤ 0.08`、`Brier ≤ 0.18`；
- 高风险分层 `ECE ≤ 0.05`；
- 难度排序与实际失败率 `Spearman ≥ 0.70`；
- 预测区间覆盖率在预注册范围内；
- 低样本和分布外任务能够回退到保守先验；
- 低价模型预计返工更贵时，执行前选择更强路线；
- 本地预计过载或错过期限时，执行前转向可行部署；
- 模型目录更新不要求增加厂商名称分支。

### 8.7 不得晋级的情况

- 样本只来自模拟执行器；
- 测试项目泄漏进入训练；
- 模型只提升平均指标但严重伤害高风险任务；
- 预测区间不报告不确定性；
- 成本模型遗漏验证、交接和返工；
- 新预测器无法回放和回滚。

## 14. 统一评测指标

### 14.1 三个主 KPI

1. **Cost per Accepted Task（CPS）**

```text
规划 + 执行 + 验证 + 工具 + 上下文搬运
+ 本地算力 + 重试 + 升级 + 返工
──────────────────────────────────
            最终验收成功数
```

2. **Verified Success Rate**

只有预注册 Success Contract 的全部硬条件通过，才记为成功。

3. **Time to Accepted Result**

从任务进入到最终可验收结果的端到端时间，同时报告 P50 和 P95。

### 14.2 诊断指标

- First-pass Success Rate；
- Retry、Escalation、Subgraph Replan、Full Replan Rate；
- Planning Cost Ratio；
- Wasted Token / Duplicate Work Ratio；
- Handoff Defect Rate；
- Budget、Permission、SLA Violation；
- ECE、Brier、区间覆盖率；
- Routing Regret；
- Local Admission Accuracy；
- Parallel Critical-path Reduction；
- 用户改写率和人工介入率；
- Cost per Accepted Image / Video Second；
- Media Rerender Ratio；
- Continuity Defect Rate；
- Energy per Validated Result。

## 15. 统一证据等级

| 等级 | 证据 | 可以支持的结论 |
|---|---|---|
| E0 | 手工规则或厂商资料 | 设计先验，不支持效果结论 |
| E1 | 确定性模拟 | 验证流程和合同 |
| E2 | 30～50 个真实任务 | 方向性信号 |
| E3 | 200～500 个隔离真实任务 | 初步任务族结论 |
| E4 | 1000+ 多任务族正式基准 | 有范围的产品结论 |
| E5 | 受控 Shadow/Canary 真实流量 | 生产策略晋级依据 |

页面、README 和发布说明必须显示结论对应的证据等级。

## 17. 现在最先执行什么

下一步不是继续增加启发式规则，而是完成 **v0.5.6.3 的真实证据门**：

1. 由用户显式选择本地或低价 Provider、配置密钥并批准一个很小的实验硬预算；
2. 从冻结任务集中选择 30～50 个方向性真实任务，保留强模型、人工静态路线和 CostWeave Shadow 建议；
3. 使用独立硬验收或人工盲评，不允许执行模型自证成功；
4. 对账真实 Token、账单、端到端时间、重试、验证和返工；
5. 生成 E2 报告，同时披露样本不足、选择偏差、失败案例和未知反事实；
6. 确认 Shadow 干预为 0、预算越界为 0、密钥扫描为 0；
7. 只有数据质量门通过后，才开始 v0.5.6.4 的校准预测器；继续禁止自动训练、策略晋级和商业效果宣传。

真实连接仍必须由用户显式配置和授权；没有密钥与预算时，系统保持零外部调用。

## 18. 最终完成定义

CostWeave 只有在以下事实同时成立后，才可以被称为经过验证的自适应多模型分流系统：

1. 对照基线、任务集和验收标准公开且固定；
2. 数据来自真实模型和真实账单，并与模拟数据严格区分；
3. 结果经过独立验收，训练和测试没有项目级泄漏；
4. 成功率、成本和时延预测完成校准；
5. 新策略先通过回放和 Shadow，再进行低风险 Canary；
6. 高风险任务探索率为 0；
7. 在成功率非劣的前提下，CPS 改善具有统计置信；
8. 所有策略可以解释、重放、冻结和回滚；
9. 失败数据与成功数据同等进入报告；
10. 任何“世界顶尖”或固定降本比例都来自可重复比较，而不是设计推断。
