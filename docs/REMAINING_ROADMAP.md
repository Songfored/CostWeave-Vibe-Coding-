## 1. 结论先行

CostWeave 当前不是缺少模块，而是缺少四条真正接通的链路：

1. **安全链**：身份、项目、地域、撤销、审批、预算、幂等、秘密和网络目的地必须由统一边界负责；
2. **决策链**：MetaController、CapabilityGraph、JointSearch、Recovery、SafeLearning 必须进入同一条权威决策协议，而不是继续作为五个旁路页面；
3. **证据链**：真实 Provider 响应、账单、缓存、重试、延迟和独立质量标签必须能够逐项对账；
4. **学习链**：成功与失败只能先产生候选策略，再经过离线、Shadow、Canary 和回滚门，不能运行几次就自行修改生产规则。

因此，接下来不新增第三层 Planner，也不继续为“功能数量”增加新的控制器。我们采用以下顺序：

```text
安全地基
  ↓
交付与版本收口
  ↓
统一决策桥（只观察）
  ↓
数据就绪主链（只激活规划拓扑，仍无付费）
  ↓
真实小预算对账
  ↓
数据校准路由与容量判断
  ↓
恢复与安全学习闭环
  ↓
竞争证明
  ↓
多模态证明
  ↓
生产化
```

## 3. 全阶段共同约束

### 3.1 管理深度固定为两层

只允许：

```text
MetaPlanner
  └─ Planner 或 MultiPlanner
       └─ Executor / Validator
```

- 不允许 Planner 再递归创建管理层；
- MultiPlanner 必须证明新增信息价值高于额外 Token、延迟和协调成本；
- 小任务允许 `NO_DELEGATION`，禁止为了多智能体形式而拆分；
- 推理强度、模型能力和权限是三个独立维度，能力升级不得自动扩大工具、数据或网络权限。

### 3.2 总成本必须按最终验收计算

唯一主要成本口径是：

```text
Total Cost =
  规划 + 上下文搬运 + 执行 + 工具 + 验证 + 等待
  + 重试 + 升级 + 恢复 + 返工 + 未确认账单

Cost per Accepted Result = Total Cost / 最终验收通过数
```

禁止只比较某一次模型请求的单价。低价模型导致的返工、高价 Validator、规划委员会开销和失败调用都必须计入。

### 3.3 真实数据不足时禁止伪装学习

- E0 模拟数据只能验证代码和合同；
- E1 公开静态数据只能验证离线路由方法；
- E2 小预算真实调用可以用于方向性校准；
- E3 受控真实 Shadow/Canary 才能支持有限运行结论；
- E4 预注册、独立复现和完整披露后，才允许公开竞争结论；
- 样本量必须由预注册的统计功效和任务分桶决定，不能为了凑固定数量盲目烧 Token。

### 3.4 所有智能能力都必须可回退

每个决策组件固定经历：

```text
offline_candidate
  → shadow_observe
  → shadow_compare
  → simulated_active
  → real_shadow
  → bounded_canary
  → active
```

任一阶段出现预算、权限、数据、质量、延迟或副作用越界，必须退回上一已知安全状态。一次发布只允许一个新的决策点取得执行权。

### 3.5 不得提前宣传的结论

在 v0.7.4 竞争证明门通过前，不得宣称：

- 固定降低 90% 成本或成本只有原来的十分之一；
- 已超过世界顶尖公司的路由系统；
- 已证明中国模型与美国模型的某种组合必然更优；
- 已实现生产级自我学习；
- 已具备真实多模态成本优势。

## 5. v0.6.7：Security Foundation Recovery

### 5.1 目标

先把已经验证的安全问题关闭，恢复“默认离线原型可安全公开”的最低条件。本版不增加路由算法，不接入真实 Provider，也不改变模型选择。

### 5.2 工作包

#### V067-WP01：立即阻断秘密回显

- Provider 输出返回或持久化前，必须检测当前 `SecretLease` 的精确值；
- 命中时拒绝该响应，只保存固定错误码和安全摘要；
- 覆盖嵌套对象、数组、流式分片和必要的编码形式；
- 日志、Trace、Receipt、SQLite 和 API 响应均运行秘密哨兵测试。

#### V067-WP02：静态文件与全部请求入口

- 拒绝绝对路径、Windows 盘符、UNC、设备路径和混合分隔符；
- `resolve()` 后验证目标仍位于固定 web 根目录；
- GET、POST、静态文件和未来方法统一执行 Host/Origin guard；
- 引入高熵本地会话令牌；项目头只能作为认证后的选择器。

#### V067-WP03：统一项目安全上下文

定义 `RequestSecurityContextV1`，至少包含：

- authenticated principal；
- project ownership；
- project active/tombstone；
- data residency；
- operation scope；
- approval scope；
- request identity。

所有 Run、Task、Artifact、Evidence、MetaController、CapabilityGraph、JointSearch、Recovery、SafeLearning 和导出服务必须接收该上下文，不允许各路由自行拼接授权。

#### V067-WP04：统一外部调用授权

定义 `ExternalCallAuthorityV1`，集中负责：

- 真实审批记录验证，而不是 approval ID 正则；
- Provider、模型、Prompt、项目、地域和预算范围绑定；
- 项目级副作用幂等与 ambiguous 状态；
- 请求前原子预算预留；
- 失败/超时的保守成本冻结与后续对账；
- 当前秘密的精确输出检查；
- 经过验证并绑定实际 peer 的网络目的地。

#### V067-WP05：有界 HTTP 并发

- 使用有界 worker pool 或 active connection semaphore；
- 超限快速失败并记录指标；
- 保留连接、请求体、响应体和单项目并发上限；
- 运行非破坏性的压力与恢复测试。

#### V067-WP06：安全回归与重新扫描

- 把本轮 11 条攻击路径全部变成确定性回归；
- 全量测试、隔离测试、wheel 安装和发布门禁重新执行；
- 再做一次标准安全扫描；
- 修复前的 PoC 必须全部失败，不能只靠修改发布门状态。

### 5.3 退出门

- 当前高危发现为 0；
- 默认可达路径不存在未缓解中危发现；
- Windows 文件越界、DNS rebinding GET、伪造审批、秘密回显、预算释放和跨实验重放 PoC 全部失败；
- 未授权调用和真实 Provider 调用仍为 0；
- 全量与隔离测试均为 0 失败；
- `production_ready` 仍保持 false。

### 5.4 停止条件

若为了统一安全上下文需要同时重写 RunManager、所有 Store 和所有 API，不得一次性大爆炸重构。先保留战术补丁，再按服务逐个迁移到统一上下文；新旧路径必须有差分测试。

## 7. v0.6.9：Authoritative Decision Bridge

### 7.1 目标

解决当前最大产品偏差：五个“聪明模块”存在，却不能共同参与一次 Run。该版本只建立统一决策桥，仍不允许新模块改变正式路线。

### 7.2 核心合同

新增 `DecisionOrchestratorV1` 与不可变 `AuthoritativeDecisionEnvelopeV1`：

```text
RunRequest
  → TaskBelief / SystemBelief
  → MetaController
  → CapabilityGraph
  → JointSearch
  → Baseline route + Shadow route
  → Runtime observations
  → Recovery advice
  → Outcome credit
  → SafeLearning candidate
```

Envelope 必须保存：

- 输入快照、目录快照、价格快照和容量快照；
- 候选管理拓扑与候选模型组合；
- 可行性、拒绝原因、成功/成本/延迟分布及置信度；
- 规划、交接、验证和恢复预算；
- baseline 与 shadow 的差异；
- 每个模块版本、证据等级和是否拥有执行权；
- 确定性指纹与选择概率。

### 7.3 接入方法

- 用 Adapter 包装现有五个服务，不先重写算法；
- 主 Run 只消费 baseline，shadow 只记录建议；
- 同一输入必须让旧路径和新路径共享目录、预算、任务合同和验收标准；
- 任何模块无法给出合法 Envelope 时，失败关闭到旧 baseline；
- 不允许 shadow 写任务状态、修改 DAG、调用 Provider 或晋级策略。

### 7.4 退出门

- 每个新 Run 都能生成 baseline 与完整 shadow decision trace；
- shadow 对正式路线、预算和外部调用的影响为 0；
- 新旧路径的输入差异为 0，差分原因全部结构化；
- 决策桥失败时 baseline 仍可完成；
- 所有五个 advisory 模块都能被同一 Run ID 和 Trace ID 追溯；
- 未出现新的第三层 Planner。

### 7.5 完成状态

- 五个既有 advisory 服务已通过 Adapter 接入同一 Run/Trace；
- baseline 与 shadow 共用同一输入指纹，结构化 `input_diff` 为 0；
- Envelope 保存四类快照、候选拓扑/模型组合、分布、预算、差异、模块版本、证据等级、选择概率和确定性指纹；
- 影子链对正式路线、预算、任务状态、DAG、Provider、网络和外部调用的影响全部为 0；
- 模块异常会生成完整失败关闭信封，baseline Run 仍可完成；
- 决策信封可随运行投影持久化，并通过只读 API 和运行页面追踪；
- 管理深度上限保持 2，v0.6.9 E0 工程退出门完成，`production_ready=false`。

## 8. Revision 8 历史方案：v0.7.0 Controlled Main-Chain Activation

> 本节至第 13 节保留用于解释旧方案的来源，不再作为施工依据。v0.7.0—v0.7.5 的当前工作包、依赖、停止条件和验收规则统一见[v0.7 重构实施路线](V0.7_RECONSTRUCTED_ROADMAP.md)。

### 8.1 目标

在仍然零付费的模拟/本地环境中，让新决策链一次只控制一个决策点，验证它不会把“大量模块”变成一团互相覆盖的状态。

### 8.2 激活顺序

1. 先控制 `NO_DELEGATION / Planner / MultiPlanner` 管理拓扑；
2. 再控制任务到模型/档位的路由；
3. 再控制并发宽度和调度；
4. 再允许 Recovery 选择 `continue/retry/switch/subgraph-replan/full-replan/stop`；
5. SafeLearning 仍不能自动激活策略。

每一步都必须有单独 feature flag、版本化策略指针、回滚命令和 baseline fallback。禁止在一个版本中同时激活多个决策面。

### 8.3 算力配置方法

每个候选策略计算：

```text
Expected Total Loss =
  失败损失
  + 模型与工具成本
  + 规划/交接/验证开销
  + 排队与期限损失
  + 风险与未知惩罚
  + 预计返工成本
```

- 简单、低风险、上下文明确的任务优先 `NO_DELEGATION`；
- 只有在信息价值大于协调成本时才启用 Planner/MultiPlanner；
- OOD、低覆盖、容量不足、失败代价高或候选效用区间重叠时，执行前升级；
- 本地高并发预测使用队列、内存、上下文长度、预计 tokens/s 和 deadline，而不是任务名称关键词；
- 若没有可信容量数据，主动 `ABSTAIN/ESCALATE`，不能假装本地模型可承载。

### 8.4 退出门

- 在固定 E0/E1 任务集上，新主链可确定性复现；
- 安全、预算、权限和重复副作用违规为 0；
- Planner 成本中位数目标不高于任务总成本的 5%（这是晋级目标，不是当前成绩）；
- 本地直接判定 P95 附加延迟目标不高于 100ms；
- Handoff Defect Rate 目标不高于 3%；
- 新路径没有净收益时自动退回旧 baseline。

## 9. Revision 8 历史方案：v0.7.1 Real Call Reconciliation

### 9.1 目标

完成原 V066-WP08，但必须建立在 v0.6.7 安全退出门之后。用最小真实预算证明每一笔调用、缓存、重试、延迟、输出和账单可以对齐，而不是证明 CostWeave 已经省钱。

### 9.2 最小实验范围

- 一个本地 OpenAI-compatible 端点；
- 两个用户显式选择的真实 Provider 协议；
- 小型、预注册、可独立验收的任务集；
- strong-only、cheap-only、人工静态路由和 CostWeave shadow 四组；
- 固定模型、价格日期、Prompt、验证器、随机种子和预算；
- 真实调用总预算由用户显式批准，达到上限立即停止。

### 9.3 对账字段

- 输入、缓存和输出 Token；
- 请求数、重试数、429/5xx、超时和 ambiguous；
- Provider 用量字段与最终账单；
- P50/P95 请求、排队和端到端延迟；
- 独立验收结果与返工次数；
- Prompt、规划、交接、验证和恢复开销；
- 不能确认的账单保持冻结，不按 0 处理。

### 9.4 退出门

- 每个样本的 Provider 收据、内部账本和实验报告可双向追溯；
- 无法对账的样本不能进入模型能力或商业结论；
- 原始 Prompt、输出和秘密遵守用户选择的数据保留策略；
- 实验失败不会扩大预算或自动重放 ambiguous 副作用；
- 本版最多形成 E2 方向性证据，不产生固定降本宣传。

## 10. Revision 8 历史方案：v0.7.2 Calibrated Routing & Capacity

### 10.1 目标

用 v0.7.1 的真实数据替换最关键的启发式常量，使任务难度、模型能力、本地容量和升级概率能够被现实证伪。

### 10.2 改进方法

- 任务难度不使用一个总分，而使用复杂度、不确定性、错误代价、知识时效、上下文长度、工具需求、验证难度和并行潜力向量；
- 模型能力按任务族、版本、推理档位、工具、上下文、Provider 和容量条件分桶；
- 同时预测 `P(accepted)`、总成本、P50/P95 延迟、返工、升级和失败类型；
- 使用分层先验处理新模型冷启动；
- 输出置信区间、覆盖率和 OOD，而不是只给一个自信分数；
- 本地容量模型消费实际 queue、RAM/VRAM、tokens/s、并发和 deadline；
- 价格或模型版本变化触发候选冻结和重新校准，不自动在线训练。

### 10.3 评估方法

- Brier score、ECE/校准曲线；
- Selective Risk-Coverage；
- Cost per Accepted Result；
- Time to Accepted Result P50/P95；
- Routing Regret；
- 升级过早率与升级过晚率；
- 本地容量误判率和 deadline miss；
- 按任务族、Provider、模型版本和价格时期分层报告。

### 10.4 退出门

- 在冻结测试集上优于静态规则，且校准没有恶化；
- OOD 和低覆盖能够 `ABSTAIN/ESCALATE`；
- 新模型没有真实数据时使用保守先验，不获得虚构高分；
- 规划器和路由器的开销计入总成本后仍有净收益；
- 任何单一任务族不能掩盖其他任务族的系统性失败。

## 11. Revision 8 历史方案：v0.7.3 Recovery & Safe Learning Loop

### 11.1 目标

让执行中证据真正改变恢复动作，同时保证成功和失败数据只改进应负责的组件，不形成无门槛在线自我修改。

### 11.2 恢复闭环

- 每个 checkpoint 更新剩余成功概率、预算、关键路径和污染范围；
- 继续、局部重试、换模型、请求信息、子图重规划、全量重规划和停止使用相同剩余损失口径比较；
- 已验证且不受污染的 Artifact 必须复用；
- 沉没成本不能成为继续错误路线的理由；
- Validator 与 Executor 失败相关性过高时，必须换异源验证器；
- 全量推倒重来必须证明局部恢复不可行或风险更高。

### 11.3 学习闭环

```text
不可变 Trace
  → 独立 Outcome
  → 标签治理
  → Planner/Router/Handoff/Executor/Validator/Recovery 分层信用
  → 候选策略
  → 离线盲测
  → Shadow
  → 有界 Canary
  → 人工或策略门激活
```

- 未独立验收的输出不能成为成功标签；
- 冲突标签并列保存，不强行覆盖；
- 无选择概率的数据不能伪装成无偏策略评估；
- 用户删除请求必须影响后续学习副本和训练集；
- 每次策略变化都能回到原始 Trace、数据版本和信用解释。

### 11.4 退出门

- Recovery Advantage 相对固定重试和一律全重做为正；
- 权限、预算和重复副作用违规为 0；
- 学习候选不能绕过 Offline → Shadow → Canary；
- 数据漂移、标签质量或校准恶化会冻结晋级；
- 回滚可以恢复上一策略而不修改历史事实。

## 12. Revision 8 历史方案：v0.7.4 Competitive Proof

### 12.1 目标

用可重复实验回答“CostWeave 是否真的比人工判断、单一强模型、低价模型和竞品路由更好”，而不是再根据架构复杂度自评。

### 12.2 三层赛场

#### L1：单请求路由

比较 strong-only、cheap-only、random、静态阈值、RouteLLM 类、LLMRouter 类和 CostWeave。使用相同模型池、价格快照、数据切分和评分器。

#### L2：完整工作流

任务必须真的包含拆解、并行、验证、返工或工具。比较：

- 单一强模型端到端；
- 人工静态分工；
- 固定 Planner；
- 固定 MultiPlanner；
- CostWeave 自适应策略；
- 用户的 Claude 版本或其他外部 Agent 的结构化 Trace。

#### L3：受控真实流量

只在 L1、L2 达标后进行 Shadow → 1% → 5% → 20% Canary。任何预算、权限、数据或显著质量越界自动回滚。

### 12.3 预注册胜出线

- L1：质量非劣界 -2 个百分点时，成本相对最佳已复现非 Oracle 基线至少低 10%；或者相同成本下成功率至少高 3 个百分点；
- L2：成功率非劣时，Cost per Accepted Result 至少低 15%，且 P95 时间不恶化超过 10%；或者形成统计显著的质量—成本—时间 Pareto 优势；
- 使用配对 Bootstrap 95% 置信区间；
- 同页披露胜出、失败、硬件、模型、价格日期、预算、偏差和消融结果；
- 未过门时发布失败报告，不修改门槛追求胜出。

这些是未来实验的预注册目标，不是当前产品成绩。

## 13. Revision 8 历史方案：v0.7.5 Multimodal Economic Orchestration

### 13.1 目标

把图片和视频创作纳入相同的成本—质量—时间控制，而不是简单把长提示词转发给昂贵生成模型。

### 13.2 工作流

```text
创作目标
  → 剧本/镜头 DAG
  → 低成本脚本与分镜检查
  → 镜头级 Prompt/Handoff 编译
  → 低分辨率或短时长 Probe
  → 人工/模型验收
  → 只升级失败或高价值镜头
  → 缓存、复用、局部重渲染
  → 全片一致性与版权元数据验收
```

### 13.3 改进方法

- 模型主动判断是否需要先润色分镜、角色、镜头、运动和风格约束；
- 相似镜头、角色设定、参考图和运动模板可复用；
- 先使用便宜 Probe 验证构图、动作和一致性，再决定高质量生成；
- 失败只重渲染受影响镜头，不默认推倒整片；
- 图片/视频模型能力、价格、分辨率、时长、并发、版权和地域信息可编辑导入；
- 每个镜头保存 Prompt 版本、种子、模型、成本、延迟、验收和重渲染原因。

### 13.4 退出门

- 以 Cost per Accepted Shot、最终可用镜头率、人工返工分钟数、P95 交付时间和全片一致性评估；
- 与“直接使用高价模型一次生成”和“人工逐镜头选择模型”比较；
- 原始素材、人物肖像、版权和训练用途有明确同意与保留策略；
- 未得到 E2+ 真实数据前不宣传视频成本优势。

## 15. 统一验收指标

| 类别 | 指标 | 使用方法 |
|---|---|---|
| 最终效果 | Verified Success Rate | 只接受独立硬验收或受治理标签 |
| 综合成本 | Cost per Accepted Result | 包含规划、验证、失败、升级和返工 |
| 时间 | Time to Accepted Result P50/P95 | 不只记录单次模型延迟 |
| 路由 | Routing Regret / Pareto | 与同模型池可行基线和 Oracle 上界比较 |
| 校准 | Brier、ECE、Risk-Coverage | 判断成功概率是否可信以及何时应放弃判断 |
| 管理 | Planner Cost Ratio | 防止 MultiPlanner 的管理成本吞噬收益 |
| 交接 | Handoff Defect Rate | 缺字段、矛盾、越权和信息损失分别计数 |
| 恢复 | Recovery Advantage | 与固定重试和全部重做比较 |
| 安全 | 权限/地域/预算/副作用违规 | 必须为 0 |
| 容量 | 队列预测误差与 deadline miss | 判断本地高并发时是否应在开始前升级 |
| 学习 | 候选晋级率、回滚率、漂移冻结率 | 不以“更新次数”冒充学习效果 |

## 16. 分层交付与验收去重

不再要求每个内部工作包重复交付全量回归、全仓安全复扫、隔离测试、双端截图和发布包。改为四级门：

1. **G0 持续快速门**：每次修改只跑语法、合同、安全不变量、确定性和受影响测试，并提交 `ChangeImpactManifest`；
2. **G1 工作包增量门**：工作包完成时只跑受影响集成、回退/失效关闭、相关攻击路径，以及发生变化的性能或迁移测试；
3. **G2 版本候选门**：每个公开 v0.7.x 候选版只做一次全量回归、发布门、构建/hash/clean install；隔离测试和双端页面验收按变更触发；
4. **G3 风险触发门**：安全边界、外部网络、预算副作用、主链权力、持久化/并发或真实数据治理变化时，才追加对应专项安全验证。

同一提交、配置、依赖锁、策略版本和环境指纹未改变时，可复用已有证据；任一指纹变化、测试失败或风险标签扩大时立即失效。完整矩阵见[v0.7 重构实施路线](V0.7_RECONSTRUCTED_ROADMAP.md)。

## 17. 低能力模型施工限制

低能力模型可以执行：

- 文档整理、版本文本统一；
- 已明确 CSS 断点和截图验收的页面修复；
- 已有模板下的测试补充；
- 确定性的字段搬运和适配器胶水；
- 清理 staging、构建脚本和静态检查。

低能力模型不得独立决定：

- 认证、项目、地域、审批和秘密边界；
- 预算结算、幂等和副作用状态机；
- 主链决策权迁移；
- 真实 Provider、付费 Canary 和数据保留；
- 学习策略晋级或安全发现关闭。

高风险工作必须由更强模型或人工评审，且修改后用原攻击路径和差分测试验收。
