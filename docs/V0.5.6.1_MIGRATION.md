# CostWeave v0.5.6.1 升级说明

v0.5.6.1 可直接覆盖 v0.5.5 程序文件并继续使用原运行数据库。首次启动会自动应用 migration 014，将 Runtime Schema 升级为 `v5.6.1`；Run Projection Schema 仍为 `v5.5`，旧运行投影无需重写。

## 数据库变化

新增 `evaluation_observations`：

- 每个报告、任务和基线只有一个观察项；
- 保存实验 ID、项目、数据分区、盲评别名和证据等级；
- 保存观察正文及 SHA-256；
- 通过外键连接既有 `evaluation_runs`，不建立第二个报告事实源；
- 同一报告写入具有幂等性，缺失或冲突的观察矩阵会被拒绝。

旧的固定预测校准评测继续保存在 `evaluation_runs`，不会被转换成 v0.5.6.1 真实任务评测。

## 新命令

仅导出文件：

```powershell
python -B -m costweave.baseline_runner --output-dir work/v0561-evaluation
```

导出并写入指定数据库：

```powershell
python -B -m costweave.baseline_runner --output-dir work/v0561-evaluation --database work/v0561-runtime.sqlite3
```

输出目录中的实验文件是不可变证据：相同内容可以重复执行，不同实验不得静默覆盖同名文件。需要运行另一组实验时，应使用新的输出目录。

## 行为边界

- 默认和命令行评测均只使用确定性 Fixture Backend；
- `real_provider_calls_allowed` 固定为 `false`；
- 参考答案、验证器身份、项目分区和路线身份不会传给执行后端；
- 盲评文件不包含模型、Provider、策略、价格或已计算软评分；
- 报告证据等级固定为 `E0-simulated`，商业声明资格固定关闭；
- v0.5.6.1 不会训练模型、晋级策略或影响正常任务路由。

## 回退

回退前先备份数据库。v0.5.5 不认识 Runtime Schema `v5.6.1` 和 migration 014，但旧 Run Projection 仍保持 `v5.5`。建议保留 v0.5.6.1 程序读取已升级数据库；若必须回退，应使用升级前备份，不要手工删除迁移记录。
