# CostWeave v0.5.6.4.4

## 新增

- 默认上限为 10 节点、100,000 组合的小型 DAG 精确穷举 Oracle。
- `optimal`、`infeasible_proven` 与 `skipped_bounds` 三态结果，避免超界伪证明。
- Beam 与 Oracle 的可行性、选择、目标值、绝对/相对 Regret 差分验收。
- 对 Beam `optimality_proven` 声明的独立核验。
- 价格、成功率下界、P95 时延和失败返工成本的离散敏感性探针。
- 最近已观察路线翻转点、相对翻转距离和四档稳健性等级。
- 32 探针、128 测试点硬上限以及只保留当前最优解的内存边界。
- migration 020 的不可变、带哈希、外键关联存储和数据库级零权威约束。
- Portfolio Policy API 与健康接口中的精确验收范围和运行计数。

## 已验证反例

专项测试构造了一个全局损失有效但局部价格有误导性的 DAG。Beam 宽度为 1 时，启发式搜索保留低价上游并产生 `0.555018` 美元预期总损失；精确 Oracle 选择强上游，预期总损失为 `0.331036` 美元，检测到 `0.223982` 美元 Regret。这是确定性 E0 工程夹具，只证明差分验收能发现剪枝错误，不代表真实业务节省。

## 硬边界

- 精确性仅针对给定离散候选、E0 输入、损失公式和硬约束。
- 超过节点或组合上限时不运行、不采样猜测、不宣称最优。
- 敏感性只覆盖实际测试点，不把最近翻转点包装成连续阈值证明。
- Oracle、差分和敏感性报告都不能改变实际路线或支持商业效果声明。
