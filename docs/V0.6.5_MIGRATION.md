# v0.6.5 migration and rollback

## Upgrade

1. Stop the local CostWeave process.
2. Install the v0.6.5 package in a fresh virtual environment or run from the
   source tree.
3. Start the runtime once. EventStore applies migration 035 and keeps WAL and
   full synchronous durability.
4. Verify runtime schema v6.5.0 and migration count 35 with the release CLI.

Migration 035 creates five immutable project-scoped record tables and one
idempotency table. It is safe to run repeatedly because EventStore records a
checksum for every migration.

## Rollback

Do not delete migration rows or edit migration SQL. Roll back the application
binary only after making a verified logical backup. A v0.6.4 binary can read
the shared database only if its migration policy explicitly accepts migration
035; otherwise restore the pre-upgrade backup into a separate database.

Safe-learning records are advisory evidence. Restoring a backup cannot grant
live route authority, training permission or Provider access.
