# V066-WP06 Runtime Backend implementation specification

## Scope

This package creates a provider-neutral execution boundary. The first
implementation is the existing local persistent runtime. A future LangGraph,
Agent Framework or other runtime must enter through the `RuntimeBackend`
protocol and must not be imported into CostWeave's control kernel.

## Contract

`RuntimeSubmitRequestV1` carries a goal, project and residency scope, execution
mode, budget/quality/deadline limits, concurrency and recovery limits, a
caller idempotency key and optional non-secret metadata. Unknown fields,
non-finite numbers, invalid identifiers and secret-bearing metadata fail
closed.

`RuntimeOperationV1` returns the operation, run ID, stable Trace ID, status,
runtime revision, replay flag and a detached run snapshot. `RuntimeEventV1`
and `RuntimeEventPageV1` expose ordered stream revisions, bounded sanitized
payloads and a `has_more` continuation signal.

## Operation rules

1. `submit` creates or replays one durable run. The same project and
   idempotency key return the same run and do not start a second worker.
2. `cancel` requires an expected revision and transitions only through the
   existing state machine. A replay is accepted before revision comparison.
3. `checkpoint` emits one durable runtime checkpoint event. Its checkpoint ID
   is deterministic for run, key and source.
4. `resume` emits one durable resume event, clears an interrupted finish time,
   marks the record recovered and asks the local manager to resume validated
   work. Terminal runs cannot be resumed.
5. `events` requires project scope, validates `after_revision` and `limit`,
   and returns a strictly increasing page.

All writes use the existing ControlKernel lock order (`record.lock` then
kernel lock) and EventStore optimistic revisions. Replay is checked before
the optimistic revision guard. A replay can never decrease a live in-memory
revision.

## HTTP surface

- `GET /api/v1/runtime/status`
- `POST /api/v1/runtime/submit` with `Idempotency-Key`
- `POST /api/v1/runtime/{run_id}/cancel` with key and `expected_revision`
- `POST /api/v1/runtime/{run_id}/checkpoint` with key and revision
- `POST /api/v1/runtime/{run_id}/resume` with key and revision
- `GET /api/v1/runtime/{run_id}/events?after_revision=0&limit=200`

The project header is authoritative. A body project that disagrees with
`X-CostWeave-Project` is rejected. Foreign projects are indistinguishable
from missing runs.

## Non-goals

WP06 does not add distributed workers, a queue service, third-party runtime
SDKs, automatic provider calls, paid calls, media execution or production
availability claims.
