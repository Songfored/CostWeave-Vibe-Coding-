# V066-WP06 migration guide

No SQLite migration and no runtime schema bump are required. WP06 is additive:
the existing run APIs and `RunManager.create/cancel/events` methods remain
compatible.

To adopt the new boundary, construct a `RuntimeSubmitRequestV1`, pass it to
`LocalRuntimeBackend.submit`, and use the returned `runtime_revision` for the
next checkpoint, resume or cancel command. Always reuse the same
`Idempotency-Key` when retrying a command. A third-party runtime must implement
the `RuntimeBackend` protocol through an adapter; it must not write the
ControlKernel or bypass project scope.

Rollback is a code/configuration rollback: stop using `/api/v1/runtime/*` and
continue using the existing `/api/v1/runs/*` endpoints. No stored event needs
to be deleted; WP06 events remain valid append-only runtime evidence.
