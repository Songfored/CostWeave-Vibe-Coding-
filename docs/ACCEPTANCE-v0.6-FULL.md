# CostWeave v0.6 系列全面验收报告

验收日期：2026-08-27  
验收对象：v0.6.0—v0.6.9 当前源码与 v0.6.9 发布物  
证据等级：E0 本地工程验证  
最终状态：**工程控制面通过；真实多模型产品、真实降本和竞品胜出未完成；`production_ready=false`。**

## 1. 结论

本轮没有发现阻断 v0.6.9 本地、离线、单进程工程范围的代码故障。源码全量、逐文件隔离、严格资源、发布门禁、归档、干净安装、CLI、本地服务、页面主流程、中途重规划、移动布局和持久化重启均通过。

但“v0.6 工程路线完成”和“CostWeave 的最终设想完全实现”不是同一个结论：

- 若基本设想指一个能够描述任务、选择规划强度、构造 DAG、进行成本感知路由、并行调度、交接、验收、恢复、追踪和安全学习候选的**可运行控制平面原型**，则已基本实现；
- 若基本设想指一个已经接入真实本地/云端模型、能够权威分流并用真实数据证明节省成本、提高成功率、自主学习和超越竞品的**实际多模型产品**，则尚未完全实现；
- v0.6.1—v0.6.5 的五个智能模块虽然已在 v0.6.9 贯通每个 Run，但仍为影子建议，无权改变正式路线；默认执行仍是 `SimulatedExecutor`；
- 当前最准确的产品定位仍是“具备较完整工程闭环的任务级经济控制面与实验平台”，不是生产级智能分流系统。

## 5. 发现的问题

### P3：v0.6.9 二次打包复现说明缺少 `--clean`

`docs/INSTALL_REPRODUCE-v0.6.9.md` 给出的打包命令在第一次构建时成功，但已存在带标记的 staging 后再次运行会按安全设计拒绝覆盖。加入公开参数 `--clean` 后，工具会验证标记并安全重建，三种发布物全部通过。

影响：不会影响首次构建或发布物内容，但会影响开发者重复执行复现步骤。建议把文档命令改为：

```bash
python -B -m costweave.release_packaging --clean --output dist/v0.6.9
```

### P3：页面中的稳定版与当前开发版口径容易混淆

页面顶部显示 `v0.6.9`，部分区域仍使用 `V0.5 STABLE`。这与“v0.5.8.4 是稳定工程基线、v0.6.9 是当前候选版”的文档定义并不矛盾，但普通用户可能理解为页面版本落后。建议将其明确改成“稳定基线 v0.5.8.4 / 当前实验控制面 v0.6.9”。

### 环境说明：默认用户目录在验收沙箱中不可写

直接启动时，当前受限验收环境不允许向 `~/.costweave` 写数据库；代码本身会创建父目录。在把 `COSTWEAVE_RUNTIME_DB` 指向允许写入的工作目录后，服务启动、运行和重启恢复均通过。这是本次执行环境限制，不判为产品代码缺陷。

## 6. 为什么不能判定“全部设想完全实现”

当前离线 Tournament 只有 4 个模拟案例，三个候选策略的声明门全部为 `insufficient_sample`；SafeLearning 使用 12 个 E0 模拟观测，并正确给出 `training_enabled=false`、`automatic_promotion_allowed=false`。这证明证据边界和失败关闭设计有效，但也说明：

- 没有真实模型输出和独立验收标签；
- 没有真实 Provider 账单、缓存、重试和失败对账；
- 没有真实本地模型容量、GPU 压力和并发数据；
- 没有主链上由新智能模块实际改变路线的受控效果；
- 没有与强学习型 Router 和成熟 Agent Runtime 的公平复现结果；
- 没有达到 30+ 样本门槛，更没有 95% 置信区间或商业胜出证据。

因此，v0.6 已完成的是**控制面结构、工程合同、安全边界、追踪和离线实验能力**；尚未完成的是**真实执行权、真实数据闭环与竞争效果证明**。
