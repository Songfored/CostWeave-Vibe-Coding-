# v0.6.6 V066-WP04 migration and rollback

## Upgrade

No database migration is required. WP04 adds no durable tables or events.
Import the local endpoint classes from `costweave.gateway_local` or
`costweave.adapters`.

```python
from costweave.adapters import (
    LocalCapacitySnapshot,
    LocalEndpointAdmissionPolicy,
    LocalEndpointConfig,
    LocalOpenAICompatibleGatewayBackend,
    OpenAICompatibleRuntimePolicy,
    StaticLocalCapacityProbe,
)

snapshot = LocalCapacitySnapshot(
    snapshot_id="capacity-001",
    source="my-local-metrics",
    queue_depth=0,
    queue_limit=8,
    available_slots=1,
    estimated_wait_ms=0,
    telemetry_age_ms=100,
)
backend = LocalOpenAICompatibleGatewayBackend(
    LocalEndpointConfig(
        backend_id="ollama-local",
        endpoint="http://127.0.0.1:11434/v1/chat/completions",
        endpoint_kind="ollama",
    ),
    policy=OpenAICompatibleRuntimePolicy(network_enabled=True),
    capacity_policy=LocalEndpointAdmissionPolicy(
        capacity_admission_enabled=True,
    ),
    capacity_probe=StaticLocalCapacityProbe(snapshot),
)
```

Replace `StaticLocalCapacityProbe` with a caller-owned probe that returns a
fresh normalized snapshot. The policy should be tuned to the local hardware;
an absent or stale reading remains a hard rejection.

`captured_at` should be produced at collection time from a timezone-aware
clock. CostWeave computes an independent age from that timestamp and uses the
greater of it and `telemetry_age_ms`; old or materially future timestamps fail
closed. Complete queue, slot, wait and age telemetry is mandatory and
`require_complete_telemetry=False` is rejected.

## Rollback

Remove the WP04 imports and use the previous WP03/WP02 backend. No database
restore or migration reversal is needed. Keep network and paid-call policies
disabled during rollback unless the caller separately reauthorizes the local
endpoint.
