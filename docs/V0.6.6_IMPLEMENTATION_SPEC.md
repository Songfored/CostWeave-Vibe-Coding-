# v0.6.6 implementation specification — V066-WP01

## Scope

V066-WP01 establishes the provider-neutral Gateway Backend boundary. The
decision plane may exchange a `GatewayRequestV1` with a backend and receive a
`GatewayResponseV1` or ordered `GatewayStreamEventV1` values. The boundary also
defines capabilities, usage, billing, errors, cancellation and an optional
provider request ID.

The core contract contains no provider SDK types, endpoint URLs, headers,
credentials, provider-specific request fields or network code. OpenAI-
compatible, LiteLLM and local endpoint implementations are separate work
packages and must be default-off.

## Contract order

1. Validate the schema version, identifiers, project scope and finite JSON.
2. Reject unknown serialized fields and secret-like metadata.
3. Validate messages, tools, structured-output options and bounded content.
4. Require explicit response status and enforce error/status invariants.
5. Keep usage and billing facts distinguishable; missing billing is zero-only.
6. Require request IDs on every response/event and monotonically increasing
   event sequences.
7. Validate the response against the request's streaming mode before the
   planner consumes it.

## Safety defaults

`public_gateway_policy()` reports `network_enabled_by_default=false`,
`provider_calls_enabled_by_default=false`, `paid_calls_enabled_by_default=false`
and `telemetry_prompt_storage=false`. This package does not open sockets or
persist prompt contents. A later adapter may only be enabled by an explicit
policy and must preserve this contract.

## Compatibility

The package release version advances to v0.6.6. The durable runtime schema
remains v6.5.0 with 35 migrations because this work package adds no tables or
events. The v0.6.5 safe-learning schema is unchanged. Existing adapter
classes remain available; the new contract is exported from
`costweave.adapters` for later backend implementations.

## Explicit non-goals

- no real provider request, local server request or paid call;
- no LiteLLM/Ollama/vLLM implementation;
- no shadow traffic, telemetry exporter or model-quality claim;
- no automatic route mutation or online learning;
- no provider credential transport through the core contract.
