# V066-WP07 Small-Budget Shadow implementation specification

## Scope

WP07 adds the first explicitly armed, hard-budgeted Shadow boundary. A Shadow
probe may observe a bounded candidate execution, while the baseline route keeps
running unchanged. The package owns admission, budget reservation, data
retention and failure isolation; a caller-supplied `ShadowProbeExecutor` owns
the actual Provider transport.

## Configuration contract

`ShadowExperimentConfigV1` requires:

- a caller idempotency key, Provider, model, local/remote deployment and
  reasoning effort;
- `metrics_only` or `metrics_and_output_hash` data scope;
- total, Provider and per-probe USD ceilings;
- logical-call, one-attempt, output-token and 24-hour expiry bounds;
- project and data-residency scope;
- explicit Shadow-only acknowledgement; and
- for live or remote calls, the applicable network/paid consent and secret
  environment reference.

Release caps are USD 5 total, 20 logical calls, one attempt per probe, 8,192
output tokens per probe and a 24-hour lifetime. Smaller caller limits are
preserved. Unknown fields, non-finite values, invalid IDs and secret-shaped
configuration values fail closed. Public session data exposes only
`secret_configured`; it never exposes the environment-variable name or value.

## Admission sequence

1. Validate and fingerprint the complete non-secret configuration.
2. Register the hard budget idempotently in `ExperimentalCallStore`.
3. Require `live_calls_requested` and the global experimental-call switch.
4. For remote deployment, require the global paid-call switch, explicit paid
   consent, a secret reference and a currently available referenced value.
5. Require an injected `ShadowProbeExecutor`.
6. Validate project scope, WorkOrder, prompt-injection boundary, baseline route
   fingerprint and output-token ceiling.
7. Atomically reserve the worst-case per-probe cost before invoking the
   executor.
8. Persist only bounded usage/cost/latency/evidence metrics and, when selected,
   an output hash.

Any failed step stops before transport where possible. WP07 deliberately has
no automatic retry because a failed or timed-out Provider call may still be
billed. If a trusted cost receipt is unavailable after execution starts, the
ledger conservatively consumes the admitted per-probe maximum. Actual cost
above the reservation freezes/fails the call through the existing budget
owner.

## Idempotency and lifecycle

The experiment ID derives from project and configuration idempotency key. The
durable experiment purpose contains the full public configuration fingerprint,
so reusing a key for different content fails even after process restart. A
probe replay returns the existing measurement and performs zero new executor
calls.

Only the budget ledger is durable. Active configuration and consent are held in
memory and must be submitted again after restart. This prevents an old consent
or secret reference from silently re-arming live execution.

## HTTP surface

- `GET /api/v1/runtime/shadow/status`
- `POST /api/v1/runtime/shadow/experiments` (`Idempotency-Key` required)
- `GET /api/v1/runtime/shadow/experiments/{experiment_id}`
- `POST /api/v1/runtime/shadow/experiments/{experiment_id}/probes`
  (`Idempotency-Key` required)

`X-CostWeave-Project` and `X-CostWeave-Data-Residency` are authoritative. A
body project or residency conflict is rejected and a foreign-project
experiment is indistinguishable from a missing one.

## Non-goals

WP07 does not ship a Provider adapter, enable network or paid calls by default,
mirror production traffic automatically, store raw model output, alter the
selected route, reconcile a Provider invoice, auto-promote a policy or make a
quality/cost/superiority claim. Reconciliation belongs to V066-WP08.
