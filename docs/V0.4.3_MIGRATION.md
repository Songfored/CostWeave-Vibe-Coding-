# CostWeave v0.4.3 迁移指南

v0.4.3 在 v0.4.2 的运行数据库上追加第二个版本化迁移，不修改或删除既有命令、事件、运行、任务、尝试和投影。

## 升级

1. 停止正在运行的旧版本服务，让后台任务完成最后一次检查点。
2. 备份 `~/.costweave/runtime-v4.sqlite3` 和模型目录。
3. 安装或解压 v0.4.3。
4. 启动服务。`EventStore` 会校验 v0.4.2 migration checksum，然后执行 `002_artifacts.sql`。
5. 请求 `/api/health`，确认：
   - `version` 为 `0.4.3`
   - `control_kernel.runtime_schema` 为 `v4.3`
   - `control_kernel.migrations` 为 `2`
   - `features.artifact_dag` 为 `true`

新增表为：

- `artifacts`
- `artifact_links`
- `task_dependencies`
- `messages`

已完成的 v0.4.2 运行保持可读。若恢复一个尚未完成的 v0.4.2 运行，已验证且仍有结构化结果的节点会被物化为 Artifact，不会重新调用执行器。

## 回滚

需要暂时停止 Artifact 写入时：

```powershell
$env:COSTWEAVE_ARTIFACT_DAG="0"
python -m costweave.server
```

此时 v0.4.2 结果字段、事件和恢复机制继续工作；已经写入的 Artifact 表不会被删除。

需要完全回到内存运行时时：

```powershell
$env:COSTWEAVE_RUNTIME_V4="0"
python -m costweave.server
```

不要手工删除 migration 2 或修改 Artifact 内容。Artifact 内容哈希不匹配会被视为完整性故障，而不是自动接受。

## API 变化

新增只读接口：

- `GET /api/v1/runs/{id}/artifacts`
- `GET /api/v1/runs/{id}/graph`
- `GET /api/v1/tasks/{task_id}`
- `GET /api/v1/artifacts/{artifact_id}`（只返回经过完整性校验的元数据，不返回内容）

原有 v0.3 和 v0.4.2 API 保持兼容。
