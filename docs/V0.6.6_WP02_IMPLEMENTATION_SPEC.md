# v0.6.6 V066-WP02 implementation specification

## Scope

WP02 maps the provider-neutral Gateway Backend contract to the common
OpenAI-compatible chat-completions wire shape. It includes an in-process Fake
Server for deterministic contract tests and a local-only HTTP transport for a
caller-supplied loopback endpoint.

## Admission sequence

1. Validate a loopback endpoint with no credentials, query or fragment.
2. Require an explicit `OpenAICompatibleRuntimePolicy(network_enabled=True)`.
3. Build a provider payload from only provider-neutral request fields; strip
   CostWeave schema fields from messages and tools.
4. Send bounded JSON with request/trace correlation and idempotency headers.
5. Map HTTP errors, JSON protocol errors, usage, billing headers and provider
   request IDs into the v0.6.6 gateway objects.
6. For streaming, emit ordered `started`, `delta`, `usage`, `completed` or
   `error` events and stop before transport when cancellation was requested.

## Safety rules

- Default policy performs no transport call.
- Only `localhost`, `127.0.0.1` and `::1` endpoints are representable.
- Remote endpoints, credentials, query strings and fragments are rejected.
- No Authorization header or secret broker is introduced by WP02.
- Provider error text is not copied into the core error message.
- Cancellation is reported as unsupported rather than falsely accepted.
- The Fake Server is an in-process test fixture and records no production
  telemetry.

## Explicit non-goals

LiteLLM, remote providers, paid calls, retry policy, distributed cancellation,
Ollama/vLLM discovery, OpenTelemetry and Shadow traffic remain later work
packages. This increment does not claim real model quality or cost savings.
