# CostWeave v0.4.6 迁移指南

v0.4.6 在 v0.4.5 数据库上追加迁移 005，不删除或重写既有运行、事件、Artifact、资源租约、审批、Placement 或成本账本。

## 升级

1. 停止旧进程，并备份 `~/.costweave/runtime-v4.sqlite3`。
2. 安装或解压 v0.4.6。
3. 启动服务；迁移会自动创建 `validation_results`、`criterion_results`、`failure_records` 和 `plan_revisions`。
4. 访问 `/api/health`，确认：
   - `version` 为 `0.4.6`
   - `control_kernel.runtime_schema` 为 `v4.6`
   - `control_kernel.migrations` 为 `5`
   - `features.evidence_recovery` 为 `true`

旧 v4.2～v4.5 投影继续兼容读取。旧运行没有证据或恢复记录时，相应查询返回空列表，不伪造历史数据。

## 回滚高级恢复

如需保留 v0.4.6 程序但关闭节点升级和重规划：

```powershell
$env:COSTWEAVE_EVIDENCE_RECOVERY="0"
python -m costweave.server
```

此模式下验收失败会直接终止运行；它不会把已拒绝结果改判为通过。已写入的验收、失败和计划修订记录保持可读，不会删除。

## 数据解释

- `validation_results` 保存一次节点尝试的总体验收与误验风险。
- `criterion_results` 保存每条成功标准的通过状态、证据引用与独立性。
- `failure_records` 保存分类信号、影响范围、恢复动作和预计恢复成本。
- `plan_revisions` 保存规划层生成的 `PlanPatch`；节点重试不创建新计划修订。
- 假阳性和假阴性风险是工程估计，需由 v0.4.7 Outcome 数据继续校准。
