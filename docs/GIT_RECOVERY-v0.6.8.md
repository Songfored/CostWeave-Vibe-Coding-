# CostWeave v0.6.8 Git 状态与恢复说明

## 当前事实

2026-08-26 在项目根目录运行 Git 状态检查时，Git 返回“不是 Git 仓库”。根目录虽然存在 `.git/`，但它不是一套可用的仓库元数据。本版没有擅自删除、覆盖或重新初始化它，因为这可能破坏用户尚未恢复的历史。

## 推荐恢复步骤

1. 先把整个项目目录复制到独立备份位置；
2. 如果 GitHub 上已有权威仓库，优先重新克隆到新目录，再把当前源码按文件差异迁入新克隆；
3. 如果没有任何远端历史，人工确认备份后，把损坏的 `.git/` 移出项目目录；
4. 在项目根目录执行 `git init`，再检查 `.gitignore` 是否排除了 `work/`、`outputs/`、`dist/`、`build/`、数据库、日志和本地代理目录；
5. 执行 `git add` 前先查看待提交文件清单，确认没有环境文件、密钥、数据库、日志或历史压缩包；
6. 建立首个恢复提交并连接新的或现有的 GitHub 远端。

## 为什么本版只记录方案

重建 `.git` 会改变版本历史和远端关联，超出普通代码迭代的安全范围。v0.6.8 已完成仓库内容边界与发布包边界；Git 历史恢复需要用户选择“以远端历史为准”还是“以当前目录新建历史”。
