# CostWeave v0.4.1 → v0.4.2 迁移说明

v0.4.2 不修改模型目录 Schema。首次启动时会在独立 SQLite 文件中自动创建运行时数据库。

## 默认数据位置

- 模型目录：`~/.costweave/model_catalog.json`
- 运行数据库：`~/.costweave/runtime-v4.sqlite3`

可通过环境变量指定运行数据库：

```powershell
$env:COSTWEAVE_RUNTIME_DB="D:\CostWeave\runtime-v4.sqlite3"
python -m costweave.server
```

## 升级步骤

1. 保留现有模型目录。
2. 使用 v0.4.2 源码或安装包替换旧版本。
3. 运行 `python -B -m unittest discover -s tests -v`。
4. 启动服务并访问 `/api/health`。
5. 确认 `version` 为 `0.4.2`、`runtime_schema` 为 `v4.2`、`journal_mode` 为 `wal`。

v0.4.1 没有运行数据库，因此没有旧运行记录可自动迁移；升级后创建的新运行会持久化。

## 临时回滚

只关闭持久运行时：

```powershell
$env:COSTWEAVE_RUNTIME_V4="0"
python -m costweave.server
```

此时旧 `/api/runs` 使用内存运行时，已有 SQLite 事件保持不变且不会被旧代码解析。删除该环境变量或设为 `1` 后重新启用。

若还需关闭 v0.4 合同守卫，可同时设置：

```powershell
$env:COSTWEAVE_CONTRACTS_V4="0"
```

不要为了回滚删除运行数据库。数据库迁移失败时应先备份文件并保留错误信息。
