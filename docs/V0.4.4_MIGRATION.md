# CostWeave v0.4.4 迁移指南

v0.4.4 在 v0.4.3 运行数据库上追加第三个版本化迁移，不删除或重写既有运行、事件、任务、Artifact、消息和血缘数据。

## 升级

1. 停止正在运行的旧版本服务。
2. 备份 `~/.costweave/runtime-v4.sqlite3` 和模型目录。
3. 安装或解压 v0.4.4。
4. 启动 `python -m costweave.server`。
5. 请求 `/api/health`，确认：
   - `version` 为 `0.4.4`
   - `control_kernel.runtime_schema` 为 `v4.4`
   - `control_kernel.migrations` 为 `3`
   - `features.parallel_runtime` 为 `true`

首次启动会创建：

- `resource_pools`
- `resource_snapshots`
- `resource_reservations`
- `cost_reservations`
- `approvals`
- `provider_circuits`

单实例异常退出遗留的活跃租约会在下次启动时安全释放，并通过健康信息的 `recovered_orphan_leases` 显示数量。

## 兼容回滚

只回退调度行为、不删除新表：

```powershell
$env:COSTWEAVE_PARALLEL_RUNTIME="0"
python -m costweave.server
```

此模式继续使用 v0.4.3 的并行执行与预算守卫，不创建新的资源或成本租约。既有 v0.4.4 表和记录保持可读。

需要保留资源准入但改用原始计划顺序时：

```powershell
$env:COSTWEAVE_SCHEDULER_POLICY="fifo"
python -m costweave.server
```

不要手工删除活跃租约或迁移记录。若要完全回退软件版本，应先停止服务、保留数据库备份，再使用功能开关启动旧执行路径。

## 明确边界

- 当前资源池容量是仿真数据，不是实际 CPU/GPU 遥测。
- 当前只支持单实例数据库所有权；不要让多个 CostWeave 进程同时接管同一运行数据库。
- v0.4.4 不接入真实模型 Provider，暂时性错误重试与熔断由测试执行器验证。
