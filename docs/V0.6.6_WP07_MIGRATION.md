# V066-WP07 迁移指南

本次不需要新增 SQLite 迁移，也不提升运行时数据库版本。WP07 继续复用迁移
016 建立的实验调用表，原有运行、网关和任务接口保持兼容。

接入供应商时，应在控制内核之外实现 `ShadowProbeExecutor`，再使用
`ProcessIsolatedShadowProbeExecutor` 包装它，并把包装后的执行器注入共享的
`SmallBudgetShadowRuntime`。供应商传输、凭据解析和账单解析仍应留在适配器内。
不得绕过 `probe()`，因为项目范围、幂等、准入和调用前的原子预算预留都由它负责。

示例：

```python
isolated_executor = ProcessIsolatedShadowProbeExecutor(
    provider_executor,
    timeout_seconds=5.0,
)
runtime = SmallBudgetShadowRuntime(
    experimental_call_store,
    executor=isolated_executor,
)
```

安全修订后，未包装的同步执行器不会被启用，阻断原因是
`shadow_executor_isolation_required`。执行器必须可被 Python `spawn` 序列化；
局部函数、闭包以及只存在于父进程内的可变状态不再受支持。单次执行的硬时限为
请求时限、包装器时限两者中的较小值，并且包装器时限不得超过 30 秒。系统最多
允许 4 个并发影子子进程；超时后会先终止、再在必要时强制杀死子进程，确认退出
后才释放项目撤销锁和并发名额。超时记为 `shadow_deadline_exceeded`，预算按已准入
的最坏成本保守结算。执行器不得创建脱离其生命周期的子进程。

重启后需要再次提交相同配置才能重新启用。持久账本会识别原有指纹和预算，但进程
内同意状态不会自动恢复；使用同一幂等键提交不同内容会安全失败。

回滚仍是代码或配置回滚：关闭实验调用开关并停止使用
`/api/v1/runtime/shadow/*`。已有账本行属于只追加证据，无需删除。
