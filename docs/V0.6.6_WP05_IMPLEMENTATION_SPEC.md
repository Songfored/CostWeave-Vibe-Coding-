# CostWeave v0.6.6 — V066-WP05 OpenTelemetry-compatible tracing

## Scope

WP05 adds a bounded, standard-library-only observability contract. It gives
each runtime run one stable 32-hexadecimal Trace ID and records local spans
for Goal, Plan, Task, Provider Call, Validation and Recovery. The exporter is
OTLP-shaped JSON for local inspection; no OpenTelemetry SDK, collector,
network socket or provider is required.

The implementation lives in `costweave.observability` and is intentionally
independent from the decision algorithms. A trace failure must not block a
run, alter a route, retry a provider call or change a persisted outcome.

## Contract

`OBSERVABILITY_SCHEMA_VERSION` is `v0.6.6-otel-v1` and the policy revision is
`otel-compatible-local-trace-v1`.

`trace_id_for_run(run_id)` derives a stable OTel-sized Trace ID from a
domain-separated SHA-256 digest. It does not expose the run ID. A root Goal
span uses the first 16 characters as its deterministic root Span ID. Child
spans use a bounded sequence and a digest. The stable Trace ID and spans that
can be derived from durable runtime events can be rebuilt after restart
without relying on a process-local UUID. Provider-call spans are process-local
and are not reconstructed in WP05.

Every `TraceSpanV1` contains:

- `trace_id`, `span_id`, and optional `parent_span_id`;
- a stage in `goal`, `plan`, `task`, `provider_call`, `validation`, or
  `recovery`;
- `start_time`, optional `end_time`, `status`, and a client/internal kind;
- bounded sanitized attributes and events;
- a schema version and redaction count.

`TraceContextV1.traceparent` follows the W3C shape
`00-<32 hex trace>-<16 hex span>-01`. Gateway requests already carry the
same Trace ID and provider adapters use it to attach a `provider_call` span
when a recorder for that trace is registered.

## Privacy and safety boundary

The following controls are non-disableable in WP05:

1. Raw prompt capture is rejected at policy construction time.
2. Secret capture is rejected at policy construction time.
3. Keys resembling API keys, authorization, bearer tokens, passwords,
   cookies, credentials or secrets are replaced with metadata-only markers.
4. Prompt-like keys (`prompt`, `content`, `message`, `input`, `output`,
   `payload`, `goal`, `context`, and similar) are replaced with a marker that
   records `redacted`, `kind`, `value_type` and optional `length`. No
   source-value digest or preview is retained. Built-in gateway hooks pass
   selected metadata rather than raw provider payloads.
5. Long unclassified strings are removed and represented by classification
   and length metadata only; no digest or preview is retained.
6. Span and event counts and attribute sizes are bounded. Overflow increments
   `dropped_span_count` instead of allocating without limit.
7. `external_export_enabled` is false by default and there is no external
   exporter in this work package. Enabling the flag cannot create network
   traffic; release readiness blocks that configuration.
8. Non-finite floats are rejected and human/OTLP-shaped/HTTP outputs use strict
   JSON.
9. Published span attributes and events are recursively frozen against caller
   mutation.

These controls are pattern- and integration-based, not a proof that arbitrary
caller-supplied attributes contain no credential. Built-in and third-party
integrations must use an allowlist and must not pass raw user/provider content,
headers, credentials or unrestricted exception text. Negative acceptance
fixtures must include Basic credentials, common aliases such as `auth` and
`pwd`, nested values and non-finite floats.

The global lookup uses a thread-safe `WeakValueDictionary`. It does not own
recorder lifetime and has no fixed-capacity-cache semantics. `RunRecord` or an
integrating caller retains the strong reference while provider spans are
needed. The per-recorder span/event/attribute limits remain the memory bound.

## Runtime integration

`RunRecord` owns a `TraceRecorder`. Its stable Trace ID is included in the
run projection, public snapshot and `observability` summary. The control
kernel adds the same ID to every durable command/event payload, including the
initial `run.created` event. Existing projection schema `v5.6` and runtime
migration set remain unchanged; old projections derive a compatible Trace ID
from their run ID.

`GET /api/v1/runs/<run_id>/trace` returns the bounded local export. The normal
run snapshot contains only a summary, not prompt-like content. `GET
/api/health` reports the public WP05 policy and labels the evidence as
`E0-local-in-memory`.

The OpenAI-compatible and LiteLLM adapters create provider-call spans only
after their existing admission gates pass. A failed or cancelled provider
response is marked `error`; adapter failures remain subject to their existing
retry and side-effect policies.

The Trace ID is durable, but the span store is in memory. Restart reconstruction
replays durable runtime events into lifecycle spans; provider-call spans are
not persisted or reconstructed.

## OTLP-shaped export

`TraceRecorder.export()` is the human-readable CostWeave contract. It includes
the policy, W3C `traceparent`, redacted spans, counts and evidence level.
`TraceRecorder.to_otel()` provides `resourceSpans/scopeSpans/spans` with
`traceId`, `spanId`, `parentSpanId`, nanosecond timestamps, typed attributes
and status codes. It is an offline serialization surface, not proof that a
collector received the trace. Strict JSON rejection of non-finite floats is a
required acceptance check.

## Explicit non-goals

WP05 does not add a span database table, durable provider-span store, collector
client, sampling service, distributed context propagation, billing
reconciliation, GPU metrics, production SLOs, automatic learning or route
intervention.
Those require separately authorized work packages and E2+ evidence.

## Exit criteria

- all required stages can be represented and share one Trace ID;
- provider adapters attach a provider span without recording message content;
- prompt/secret tests, including Basic and alias fixtures, fail closed and
  exported JSON contains no raw fixture value;
- non-finite numbers are rejected and exported values are strict JSON;
- bounded storage and event-derived restart replay are deterministic;
- provider spans are explicitly verified as process-local rather than durable;
- durable event payloads, projection and trace endpoint agree on the Trace ID;
- external export, prompt capture and secret capture remain release-blocking
  when requested;
- prior gateway, contract, server and release suites remain green.

`engineering_ready=true`; `production_ready=false`. Provider-call spans remain
process-local, and collector/distributed/production claims remain outside WP05.
