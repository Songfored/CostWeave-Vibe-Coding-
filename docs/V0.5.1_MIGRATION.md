# CostWeave v0.5.1 升级说明

## 升级结论

v0.5.1 可以直接覆盖 v0.4.9 的程序文件并继续使用原运行数据库。首次启动会自动应用 migration 009，把 Runtime / Projection Schema 升级到 `v5.1`。模型目录格式没有变化。

## 新增内容

1. 两层规划合同：MetaPlanner 为第 1 层，Planner 为第 2 层。
2. 六种规划模式和不可递归的管理硬限制。
3. 领域、经济、风险三个跨厂商角色。
4. Provider-neutral Adapter 接口与默认零付费的 MockProvider。
5. 每次运行的 PlanningDecision 和 PlanProposal 回执。
6. 规划决策页面，以及策略和单次运行查询 API。

## 数据迁移

- migration 009 只增加 `events(kind, occurred_at)` 审计索引。
- PlanningDecision 与 PlanProposal 存在权威 Run Projection 和事件流中，不建立第二套可变决策表。
- v4.9 Projection 缺少 `planning` 字段时会以空回执恢复，不影响旧任务、Artifact、成本、媒体和验收数据。
- migration 有校验和且只执行一次。

## 默认安全边界

- 默认 Adapter 是 MockProvider。
- `paid_calls_enabled` 固定为 `false`。
- v0.5.1 没有真实 Provider 密钥入口，也不会发起外部模型请求。
- Planner 不能创建 Planner、改变预算或执行不可逆动作。
- 单轮最多 3 个 Planner、1 次裁决、1 次全局重规划。

## API

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/v1/planning/policy` | 读取模式、角色、管理硬限制和 Adapter 默认策略 |
| `GET` | `/api/v1/runs/{id}/planning` | 读取本次运行的决策和提案回执 |

现有 `/api/runs` 与 `/api/v1/runs` 接口保持兼容；完整运行快照增加 `planning` 字段。

## 回滚

升级前应先使用 v0.4.9 的备份接口建立数据库备份。v0.5.1 没有删除旧列或旧表，但 v0.4.9 不识别 `v5.1` Projection，因此可靠回滚方式是恢复升级前备份，而不是让旧程序直接写入升级后的数据库。

## 明确未完成

v0.5.1 只冻结合同并提供确定性模式仿真。下列内容属于后续版本：

- v0.5.2：难度向量、VoD、置信区间、实时容量和 Planning Governor。
- v0.5.3：真实受限 MultiPlanner 提案、裁决和分歧处理。
- 真实 OpenAI-compatible、本地 HTTP 和自定义 Provider 连接。
