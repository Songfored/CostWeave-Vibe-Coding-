# v0.6.1 migration notes

## Compatibility

- Stable baseline: `v0.5.8.4`.
- Previous lab: `v0.6.0` / runtime schema `v6.0.0` / 30 migrations.
- Active line: `v0.6.1` / runtime schema `v6.1.0` / 31 migrations.
- Migration 031 is append-only and leaves migrations 001–030 untouched.

Existing databases are upgraded automatically by `EventStore`. The new tables share the existing SQLite/WAL runtime; no second database is created:

- `meta_decisions_v061`: immutable project-scoped MetaDecision records.
- `meta_decision_idempotency_v061`: immutable request-key to decision bindings with request hashes.
- `planning_budget_accounts_v061`: immutable multi-dimensional budget definitions.
- `planning_budget_events_v061`: immutable reserve/release/commit ledger events.

## API and CLI

The loopback endpoints are advisory and offline:

```text
GET  /api/v1/meta-controller/status
POST /api/v1/meta-controller/decide
GET  /api/v1/meta-controller/{decision_id}
```

POST requests must include `Content-Type: application/json`, an `Idempotency-Key` of 8–200 characters, and `confirm: RUN_META_CONTROLLER`. Reusing a key with different request content is rejected with a conflict. `python -B -m costweave.meta_controller_cli --pretty` runs without persistence; `costweave-metacontroller --pretty` is the installed-console equivalent.

## Rollback

Rollback means selecting the v0.5.8.4 stable route or retaining v0.6.0 tournament-only behavior. Do not delete migration rows or edit migration 031 after a database has applied it. The new tables are advisory records and never change the stable execution route.
